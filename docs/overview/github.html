    Patchbay

    요구사항63 테스트로 확인56/63 전체 시험1,332 통과 MCP 도구23

    작성일 2026-10-24 · 숫자마다 기준일이 다르며, 맨 아래 숫자의 출처에 적었습니다.

    개요

    목표

    사용자의 요구사항을 구체적이고 명확하게 하여, 완성도 높은 아키텍처 구현을 지원한다.

    LLM(대화형 AI 모델)과 함께 프로젝트를 만들면 요구사항은 대화 속에 흩어지고, 구현이 그 요구사항을 지키는지는 다시 물어봐야 압니다. Patchbay는 요구사항을 대화로 끌어내 설계로 굳히고, 구현과 테스트가 그 설계를 지키는지 그림으로 대조하는 로컬 작업 화면입니다.

    • 지금까지의 방식: Claude에게 설계 구조나 진행 과정을 물어서 파악했습니다. 답은 글로 오고, 한눈에 그림으로 보이지 않습니다.
    • Patchbay의 방식: 요구사항 · 설계 · 테스트 결과를 파일로 남기고, 화면은 그 파일을 그립니다. 채팅에서 한 일도 화면과 파일에 남습니다.
    • 모델과 규칙의 나눔: 사람의 말과 코드를 읽고 판단하는 일만 모델이 맡습니다. 흐름도 그리기, 차단, 백업, 사용량 표시는 규칙이 합니다.

    참고

    조작은 Claude Code · Codex · 터미널에서 하고, 결과는 이 Mac의 브라우저 콘솔(127.0.0.1)에 나타납니다. 설계와 작업 기록은 이 Mac에 저장합니다. 외부 모델을 쓰면 대화와 필요한 자료가 그 서비스로 전달되고, 문서 발췌는 자료마다 허용한 것만 보냅니다.

    한 바퀴: 설계 → 구현 → 테스트 → 검토

    프로젝트는 이 고리를 돌도록 설계되어 있습니다. 각 단계는 앞 단계의 결과만 받아서 시작하고, 앞이 비어 있으면 다음 단계는 잠깁니다. 검토에서 반려되면 이유를 들고 설계로 돌아가 다음 판을 만들고, 승인되면 그 판이 결과가 됩니다.

    지금은 설계 · 구현 · 테스트가 동작하고, 대시보드가 이 고리를 표시합니다. 검토에서 승인 · 반려를 기록하고 다음으로 넘기는 화면은 다음 판에 만듭니다(R4.1a).

    참고

    초록 칸은 동작하는 단계, 점선 칸은 아직 화면이 없는 단계입니다. 실행 기록을 쓰는 4 지식 그래프 · 5 문서 호출 단계는 테스트에서 설계의 노드를 모두 한 번 이상 지난 뒤 열리고, 이미 구현된 프로젝트의 길에서는 닫혀 있습니다. 왼쪽 도구 칸의 문서 기반 지식 그래프 · RAG는 이 단계 상태와 상관없이 쓸 수 있습니다.

    설계 파일(IR): 노드 · 상태 · 연결 · 도구 · 권한 · 문서 · 평가를 기계가 읽을 수 있게 적은 설계. 판: 채택된 설계의 버전. 새 판을 채택해도 이전 판과 그 평가 결과는 지우지 않고 보관합니다.

    주요 기능

    기능은 Patchbay 자신의 설계에 적힌 요구사항 묶음(R1~R9)을 따라 나눴습니다. 오른쪽 칸의 숫자는 그 묶음의 요구사항 중 기존 테스트로 확인된 수이고, 확인된 56개는 2026-10-23 실행에서 모두 통과했습니다.

    기능별 동작

    그림은 대부분 Patchbay가 자기 자신을 프로젝트로 등록해 쓰고 있는 2026-10-24 화면입니다. 지식 그래프 · RAG 그림만 예외이고, 그 절에 따로 적었습니다. 그림을 누르면 크게 봅니다.

    대시보드 · 프로젝트의 지금을 한 화면에

    R1 프로젝트와 화면6/6 통과

    프로젝트를 열면 늘 대시보드가 먼저 열립니다. 스크롤 없이 진행 흐름, 할 일, 기록이 한 화면에 모입니다.

    1. Workflow가 설계 → 구현 → 테스트 → Review → 결과 고리를 그리고, 지금 단계를 주황으로 표시합니다. 반려되면 설계로 돌아가는 선도 함께 있습니다.
    2. 그 아래 작업 표가 지금 단계의 작업을 보입니다. 행을 누르면 세부 항목이 펼쳐집니다.
    3. 오른쪽에 Tasks(할 일), 아래에 History(기록)와 캘린더가 있습니다. 캘린더 날짜를 누르면 그날의 기록만 봅니다.
    4. 이어하기는 다른 화면에서 하던 작업으로 돌아가고, 개요는 이 문서를 엽니다. 상단 이름을 더블클릭하면 표시명과 실제 폴더 이름을 함께 바꿉니다.

    요구사항 설계 · 말한 것을 설계로 굳힌다

    R2 요구사항과 설계6/6 통과

    요구사항은 대화로 끌어내고, 절마다 사람이 확인한 뒤에야 설계로 채택됩니다. 모든 줄에 출처가 남습니다.

    1. 상담: 대화방에 등록한 LLM(Claude Code · Codex) 중 하나에게 상담을 맡깁니다. 목표 · 시나리오 · 환경 · 제약 · UI · 보안 · 미비 일곱 영역을 차례로 묻고, 답은 오른쪽 요약에 바로 쌓입니다.
    2. 요구사항: 요구사항이 많아도 개요와 초점으로 봅니다. 하나를 고르면 왜 · 무엇 · 경계 · 확인 · 연결 · 미결 여섯 칸, 변경 전후, 관련 흐름과 시험, 그 문장이 나온 대화 근거가 함께 보입니다.
    3. PRD 검토(제품 요구사항 문서): 설계 초안을 11개 절로 보입니다. 줄마다 출처(말함 · 해석 · 기본값)가 붙고, 절마다 「맞아요」나 「고쳐 주세요」를 누릅니다. 옆의 아키텍처 그림도 같은 초안에서 그려집니다.
    4. 채택: 11절이 모두 「맞아요」이고 설계 규칙 검사를 통과해야 채택할 수 있습니다. 검사는 모델 없이 돌고, 실패하면 돌아갈 칸을 짚습니다. 채택은 사람만 누릅니다.

    아키텍처 · 설계를 그림으로 보고 실물과 맞춘다

    R3 구현과 아키텍처5/5 통과

    실행 · 구조 · 흐름 세 장으로 나눠 봅니다. 실행 장은 승인된 설계에 실제 상태를 겹치고, 구조 · 흐름 장은 프로젝트에 적어 둔 구조도 문서를 그립니다.

    1. 실행: 설계의 노드마다 지금 상태를 겹칩니다. LangGraph(에이전트 그래프를 실행하는 도구)로 만든 프로젝트는 실행 상태를 겹치고 그래프 전체나 노드 하나를 실행할 수 있습니다. 이미 구현된 프로젝트는 그 노드의 요구사항을 지키는 테스트가 통과했는지를 겹칩니다.
    2. 노드를 누르면 오른쪽에 그 노드의 요구사항과, 요구사항마다 이은 테스트 파일과 결과가 나옵니다.
    3. 구조: 프로젝트의 구조도 문서를 읽어 시스템이 무엇으로 이루어지고 데이터가 어디에 저장되는지 그립니다. 요소를 누르면 하위 분해로 들어갑니다.
    4. 흐름: 같은 구조도 문서로 한 가지 일이 어떤 순서로 처리되어 저장되는지 시나리오를 그립니다.

    구현 · 테스트 · 요구사항마다 지키는 테스트를 잇는다

    R4 개발 주기와 평가4/5 통과

    구현 단계는 처음 만드는 프로젝트인지, 이미 구현된 프로젝트인지에 따라 두 길로 나뉩니다.

    1. 처음 만드는 프로젝트: 채택한 설계에서 LangGraph 뼈대와 실패하는 평가 시험을 한 번 생성합니다. 빈 노드를 모두 채워야 구현을 지납니다. 다시 생성해도 사람이 고친 부분은 덮지 않습니다.
    2. 사용 창: 처음 만드는 프로젝트의 테스트에서는 만든 서비스 화면을 Patchbay 안에 띄워 직접 써 봅니다. 아래 「실행 기록」을 열면 실행 내역과 설계 대조 결과가 나옵니다. 설계의 노드를 모두 한 번 이상 지나야 테스트를 지납니다.
    3. 이미 구현된 프로젝트: 요구사항마다 그것을 지키는 기존 테스트를 잇습니다. 에이전트가 연결을 제안하면 사람이 테스트 본문을 보고 확정합니다.
    4. 이은 테스트 실행은 확정한 연결이 들어 있는 테스트 파일을 프로젝트의 vitest(테스트 도구)로 돌린 뒤, 이은 테스트의 결과만 골라 요구사항별 통과 · 실패를 표시합니다.
    5. 실행이 실패하면 그 기록으로 평가 케이스 초안을 만들고, 설계 단계에서 검토해 채택합니다. 새 판이 나오면 이전 판과 평가 점수를 비교합니다.

    대화방과 에이전트 · 여러 LLM을 한 방에서

    R6 대화와 에이전트9/9 통과

    프로젝트마다 대화방을 두고, 등록한 LLM을 참여자로 불러 같은 기록을 함께 쓰게 합니다.

    1. LLM 호출에서 Claude Code · Codex · Grok · LM Studio(로컬) 모델을 고르고 역할명 · 아이콘 · 주요 역할을 정해 Agents 목록에 등록합니다. 방마다 켜고 끕니다.
    2. 새 대화는 모델을 고르지 않은 상태로 시작합니다. Record는 모델을 부르지 않고 기록만 하고, Send는 켜진 모델을 부르고, Stop은 실행 중일 때만 멈춥니다.
    3. 작업 모드(토의 · 보고서 · 플래닝 · 디자인 · 스터디 · 코딩)를 고르면 그 모드의 참여 모델 · 권한 · 규약이 적용됩니다. 토의는 Claude가 주장, Codex가 반론, Grok이 빠진 점, 로컬 모델이 정리하는 순서로 돕니다.
    4. 문서 · URL · 프로젝트 파일을 첨부하고, 답에 나온 산출물 링크는 새 탭으로 열거나 내려받습니다.
    5. 폰의 Claude 앱에서 Remote Control로 이 Mac의 Claude Code 세션을 쓰거나 터미널에서 Claude Code를 쓸 때, 그 세션을 대화방에 묶으면 설치해 둔 훅이 대화를 옮겨 적습니다.

    할 일과 승인 · 미리 준비하고, 승인한 뒤 실행한다

    R7 작업과 승인10/10 통과

    작업 중 생긴 후속 일은 할 일로 모입니다. 실행 전에 계획과 완료 조건을 사람이 승인합니다.

    1. Tasks에 할 일이 모입니다. 길게 눌러 순서를 바꾸고, 할 일마다 전용 대화를 엽니다. 완료하면 완료 시각과 함께 보관되고, 지운 것은 휴지통에 4일 남습니다.
    2. 자동 업무 수행: 최대 5개와 주 담당 LLM을 고르면 할 일마다 계획 · 앞선 할 일과의 연계 · 산출물을 미리 준비합니다.
    3. 준비본(계획과 완료 조건)을 사람이 승인해야 실행합니다. 실행 뒤에는 완료 조건마다 검증 근거가 있어야 완료로 봅니다.
    4. 하나를 보류하면 그 결과에 기대는 뒤 할 일은 멈추고, 관계없는 할 일은 계속합니다.
    5. 폰으로 맡긴 일은 1시간 안에 결과를 내도록 시간을 재고, 넘기면 Workflow에 표시합니다. 준비본의 승인 · 보류 · 수정 요청은 폰에서도 PC에서도 합니다.

    기록과 리포트 · 무엇이 언제 바뀌었나

    R8 기록과 리포트3/8 통과

    진행 보고 · 대화 · 할 일 · 커밋을 날짜별로 모아 하루 기록과 색인을 만듭니다.

    1. 날짜를 고르면 그날의 진행(요청과 반영), 대화, 할 일 변동이 한 문서로 보입니다. 캘린더의 색은 그날 사건 수입니다.
    2. 태그(UI · Agent · 데이터 · 서버 · 문서)로 색인하고, 아래 색인 표에서 종류별로 거릅니다.
    3. 이 날 확정으로 그날 기록을 굳히고, 고른 로컬 모델로 요약합니다. 일 · 주 · 월 보고서 바탕도 만듭니다.
    4. 할 일이나 흐름도 항목을 지우거나 고치면 저장할 때 앞뒤를 비교해 한 줄씩 기록에 덧붙입니다.

    남은 것

    구조 변경 감지(R8.3 묶음 5개)가 아직 없습니다. 추후 진행에 적었습니다.

    지식 그래프 · RAG · 근거가 있는 관계와 답

    R5 지식 그래프와 질의4/4 통과

    고른 문서에서 관계를 뽑되, 원문 인용으로 확인한 것만 그래프와 답변에 씁니다.

    1. A · 근거 검토: 마크다운 · 텍스트 문서(최대 10개)를 불러와 관계 후보(주어 · 관계 · 대상)를 직접 적거나, 고른 LLM(Claude · Codex · LM Studio)으로 뽑습니다. 정확한 원문 인용이 있어야 후보로 저장됩니다.
    2. 근거마다 승인 · 기각 · 철회를 기록합니다. 원문이 바뀌면 근거가 아직 맞는지 다시 확인합니다.
    3. B · 관계 탐색: 승인된 관계만 Neo4j(그래프 데이터베이스)에 반영합니다. 개체를 누르면 직접 이웃과 원문 근거가 보입니다.
    4. RAG(문서에서 근거를 찾아 답하는 기능): 검색에 쓸 자료를 고르고 질문하면 먼저 모델 없이 본문을 찾습니다. 답변 모델을 직접 고르면 문장마다 인용 번호가 달린 답을 만들고, 번호를 누르면 같은 원문 버전이 열립니다.
    5. 모델은 자동으로 고르지 않습니다. 외부 모델에는 자료마다 발췌 전달을 허용한 것만 보냅니다.

    그림 출처

    아래 두 그림은 2026-10-17 기능 검증 때 임시 프로젝트에서 가상 문서(guide.md)로 찍은 화면입니다. RAG 그림의 답변은 검증용 모의 모델이 낸 예시입니다. Patchbay 프로젝트에는 아직 넣은 자료가 없습니다.

    R9 원격 연결과 보안9/10 통과

    Claude Code 같은 호스트가 Patchbay를 도구로 쓰고, 그동안 지켜야 할 경계는 규칙이 막습니다.

    • MCP 서버 · CLI: MCP는 AI 도구가 바깥 프로그램을 부르는 연결 규약입니다. Claude Code 같은 호스트가 23개 도구(list_projects · get_prd · room_bind · progress_write 등)로 프로젝트를 읽고 기록하고, 터미널에서는 patchbay 명령으로 같은 일을 합니다.
    • 폴더 · 문서: 프로젝트 기록을 트리로 보고, 편집 가능한 파일만 고칩니다. 저장할 때 형식을 검사하고 내용 해시로 충돌을 막습니다.
    • 민감도 L4(비밀): 원문 조회 · 발췌 · 그래프 조회 · 편집기 저장을 막습니다.
    • 프로젝트 밖 쓰기 차단: 대화방에 묶이고 훅이 설정된 Claude Code 세션은 파일 쓰기 도구와, 알아볼 수 있는 셸 쓰기 명령의 경로를 검사받습니다. 그 프로젝트 폴더 · 작업 공간의 프로젝트 기록 폴더 · 임시 폴더 · Claude 기억 폴더 밖이면 막습니다.
    • 지우기: 대화방 · 할 일 같은 기록은 휴지통에 4일 두고 되살릴 수 있습니다. 묶인 세션이 알아볼 수 있는 삭제 명령을 쓰면, 범위 안이어도 사람의 승인을 묻습니다.
    • 백업과 공개: 작업 공간을 비공개 저장소에 백업하고, 공개 저장소로 push할 때 다른 프로젝트 이름이 나가지 않는지 검사합니다.
    • LLM 구독 체력: 왼쪽 아래에 Claude · Codex 사용량을 띄웁니다. Claude는 서버가 주는 5시간 · 7일 사용률을 씁니다.
