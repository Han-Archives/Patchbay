# 할일 기능 구현 — 2026-10-14

## 승인과 범위

사용자는 할일 시안을 승인하고 대화창에 시안 예시 제목·안내 문구를 넣지 말고 할일 쪽만 변경하도록 요청했다. 대화창 UI는 변경하지 않고 기존 대화 생성·이동·시작 흐름을 연결했다.

## 반영

- 제목 오른쪽 날짜, 오른쪽 끝 +: 제목과 요구사항을 입력해 하단에 등록한다. 각 항목에도 등록일을 표시한다.
- ‘다음 할 일’ 문구를 제거하고 원형과 세로 연결선을 표시한다. 연결된 방의 실제 실행 중에만 보라색 점멸을 켠다. 동작 줄이기 설정에서는 고정 불빛을 쓴다.
- 드래그 손잡이, 위아래 방향키, 메뉴의 위로/아래로 이동으로 순서를 서버에 저장한다. 실행 중인 항목은 고정한다.
- … → 대화창 만들기: 실제 제목·요구사항만 저장한 전용 대화를 만든다. 기존 대화는 재사용한다. 대화 생성만으로 모델을 호출하지 않는다.
- 연결된 할일의 실제 작업 호출은 맨 위 미완료 항목부터 허용한다. 앞선 할일을 완료하거나 순서를 바꾸면 다음 작업을 시작할 수 있다. 연결되지 않은 기존 대화는 이 제한의 대상이 아니다.
- 완료 처리 시 취소선, 완료 날짜·시간, 하단 완료 목록으로 이동. 한 행 높이이므로 2건부터 스크롤한다. 72시간 후 화면에서 숨기고 기록은 유지한다.
- 완료 즉시 `~/.patchbay/projects/<alias>/todo-history/`에 index.json·index.md 테이블, 해시 폴더의 task.json·summary.md·conversations/*.json·*.md를 저장한다. Agent의 작업이 끝나면 화면이 닫혀 있어도 보관하며, 이후 대화 갱신도 조회 때 반영한다. 파일은 추후 RAG 색인에 연결할 수 있는 원문이고 벡터 검색 자체를 추가한 것은 아니다.
- 기록 보기에서 제목·요구사항·ID를 검색하고, 항목을 선택해 보관된 대화 원문을 조회한다.

기존 완료 항목에 없던 completedAt은 전환 시점에 기록한다. 새 완료는 실제 완료 처리 시각을 기록한다. 기존 자동 단계·막힘 항목과 localStorage 완료 표시를 서버 목록으로 통합한다.

## 검증

- Core 빌드, Flow 형검사·프런트엔드·서버 빌드 통과.
- 할일 저장/보관 4개, 할일 동작 5개, 대화방 15개, 대시보드 6개, 운영 실행 10개, 이벤트 10개, 파일 감시 5개: 서로 다른 시험 총 55개 통과.
- 파일 감시 시험은 샌드박스 EMFILE로 처음 실패했고, 제한 밖 재실행에서 5개 통과했다.
- 실제 빌드 브라우저: 추가, 드래그, 새로고침 후 순서 유지, 전용 대화 재사용, 실제 실행 상태 점멸과 중지, 완료 목록 스크롤, 3일 표시 제한, index와 대화 원문 보관, 모바일 메뉴 이동과 가로 넘침 검증.
- 기존 4318 서버의 진행 중 작업이 없는 상태를 확인하고 같은 설정으로 재시작했다. 새 할일 API와 기록 대화상자의 실제 응답을 확인했다.
