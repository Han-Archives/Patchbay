왼쪽 RAG를 질문 중심으로 개편합니다. A+B의 자료를 재사용하고, 원문 검색과 모델 답변을 직접 선택합니다.

기획 시안 · 제품 미구현

추천 방향: 원문 검색 + 선택적 근거 답변

RAG는 질문에 맞는 자료를 찾아 모델에 제공해 답변하는 방식입니다. A+B는 지식을 만들고 검토하는 곳, RAG는 그 자료를 꺼내 쓰는 곳으로 연결합니다.
01 / SOURCE
자료 선택A+B와 같은 원문·버전
→
02 / FIND
질문으로 찾기본문 단어 + 선택적 의미 검색
→
03 / VERIFY
근거 확인원문 문단·절·현재 버전
→
04 / ANSWER
모델로 답변직접 실행 · 문장별 출처

지금은 1~2홉 연결의 문서 이름·경로·설명만 찾습니다. 본문 질문에 대한 답변은 만들지 않습니다.

사용자가 얻는 것

질문 → 답 → 원문이 이어집니다

본문을 찾고, 필요하면 답변을 생성합니다. 인용을 누르면 같은 버전의 원문을 바로 확인합니다.

실행 제어

모델은 직접 고르고 실행합니다

Claude·Codex·LM Studio 중 고른 공급자부터 검증합니다. 의미 검색의 임베딩 계산도 별도로 알립니다.

기존 지식 그래프와 연결

  • 선택한 원문문서 본문을 참고할 수 있다는 뜻입니다.
  • 검토 승인한 관계A+B에서 승인한 인용 근거입니다. 검색 보강 효과를 검증한 뒤 P5에서 추가합니다.
  • 같은 원문 목록원문은 공유하고 RAG 검색 사용과 그래프 사용은 별도로 관리합니다.

작게 시작할 범위

  • 현재 프로젝트의 선택 MD/TXT첫 파일럿 10개 이내. 사용자 자료는 직접 선택합니다.
  • 답변 + 출처 + 부족·충돌 상태검색만 만든 단계를 RAG 완성으로 표시하지 않습니다.
  • 기존 설계 연결 검색 유지기존 CLI·MCP 의미를 보존해 고급 기능으로 제공합니다.

이 문서는 제안입니다. 아래 화면의 자료·질문·답변은 모두 가상 예시이며 모델을 실행하거나 자료를 저장하지 않습니다.

P0 / 기준

자료·인용 계약

자료 ≤10개, 질문 30개. 자료 사용·철회·버전·접근·전달·실행 한도를 확정합니다.

P1 / 검색

본문과 원문 이동

질문만으로 찾고 원문·버전을 확인합니다. 기존 연결 검색은 보존합니다.

P2 / 첫 완결

출처가 달린 답변

사용자가 고른 한 공급자부터 인용·부족·충돌·중지·개정·철회를 검증합니다.

P3 / 의미

로컬 의미 검색

임베딩 준비·미적재 안내·세대 교체. 단어 기준선과 비교해 채택합니다.

P4 / 활용

보관·대화 첨부

추가 공급자 검증, 명시적 보관, 구조화된 근거 첨부와 대화 전송 검사를 갖춥니다.

P5 / 관계

승인 관계 보강

관계 추가 효과를 비교해 채택합니다. 전역 요약과 새 검색 서비스는 후속입니다.

검색과 답변 품질을 따로 측정

상위 5개 근거 적중, 첫 정답 순위, 답변의 근거 충실성, 인용 정확성, 보류 판단, 검색·생성 시간과 메모리를 기록합니다. 30개 질문의 결과를 일반 성능 보장으로 표현하지 않습니다.

반드시 막아야 하는 오류

철회 자료 노출, 다른 프로젝트 응답 혼입, 없는 인용 수용, 중지 후 정상 확정, 개정 전 원문을 최신으로 표시하는 오류는 출시 차단 조건입니다.

핵심 반영 결과
① 자료 사용과 철회 분리

RAG 검색 사용을 꺼도 A+B 관계와 원문 이력은 보존합니다. 접근 권한 철회는 모든 참조 경로에 적용합니다.

② 인용을 버전·범위에 고정

불변 원문 버전과 문자 범위·해시로 근거를 식별하고, 문장별 인용 문구를 검사합니다.

③ 대화 전달은 구조화 첨부로

첫 범위에서 제외합니다. 이후 대화 모델의 전달 허용을 다시 확인해 로컬 전용 자료의 원격 전송을 막습니다.

④ 모델 선택과 실행 제어 보존

사용자가 고른 공급자부터 검증합니다. 임베딩 모델이 미적재면 자동 적재 대신 단어 검색으로 진행합니다.

30문항은 초기 점검 세트입니다. 실제 전달 문단 수·필수 근거와 품질·지연을 따로 비교합니다.
