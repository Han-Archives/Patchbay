# 화이트 테마 화면별 시안

작성일: 2026-10-29 (Asia/Seoul) · 상태: 디자인 제안, 사용자 검토 전

사용자 요청: 다크 버전인 Patchbay를 화이트 버전으로 바꾸기 전에 디자인 안을 제시하고, 각 화면을 어떻게 진행할지 그려 달라는 요청.

산출물: [화면별 인터랙티브 시안](화이트테마-화면별시안_20261029_v1/index.html), [전체 화면 갤러리](화이트테마-화면별시안_20261029_v1/gallery.html), [전체 화면 이미지](화이트테마-화면별시안_20261029_v1/all-screens.png), [검증 결과](화이트테마-화면별시안_20261029_v1/validation.json).

현재 콘솔을 읽고 화면 구성과 실제 대시보드를 확인했다. 흰색 본문, 옅은 회색 작업 영역, 진한 상태 색을 사용하는 안이다. 현재 화면을 단순화한 독립 HTML이며, 수치·문서·실행 결과·대화는 모두 예시다. 제품 화면이나 채택된 설계는 이번 작업에서 수정하지 않았다.

## 공통 색상 제안 (웜 스톤 5단 위계)

| 역할 | 색 | 처리 |
| --- | --- | --- |
| 입력·활성 컨트롤·노드 | `#FFFFFF` | 가장 위에 떠오르는 순백 표면 (`--surface-pure`) |
| 본문 카드·패널 | `#FAF8F3` | 눈부심을 줄인 소프트 아이보리 표면 + 미세 그림자 (`--chrome`) |
| 우물·보조 표면·헤더 | `#F0EDE4` | 표 머리·다이어그램 바닥·대화 스트림 바닥·파일 트리 (`--elevated`) |
| 작업 영역 캔버스 | `#E8E5DC` | 카드와 분명히 분리되는 웜 스톤 바탕 (`--bg`) |
| 좌측 내비게이션 레일 | `#DDD9CE` | 화면 가장자리를 잡아주는 스톤 프레임 (`--rail-bg`) |
| 본문 | `#1C1E21` | 높은 가독성의 차콜 본문 |
| 보조 글자 | `#575C64` | 보조 설명·메타데이터 |
| 구획선 | `#CFCBC0` | 카드·표·패널 구획 (`--stroke`) |
| 강한 경계 | `#949084` | 입력창·선택·조작부 경계 (`--stroke-strong`) |
| 완료·통과 | `#5F2EB8` | 옅은 보라 바탕 (`#EBE3FA`), 테두리 (`#C4ACEE`) |
| 현재·확인 대기 | `#8A4706` | 옅은 주황 바탕 (`#FAE9CF`), 테두리 (`#DFB171`) |
| 실패 | `#B02E2E` | 옅은 빨강 바탕 (`#FAE4E4`), 테두리 (`#DFA3A5`) |

대비 수치는 지정 색과 흰색의 sRGB 상대 휘도로 계산한 값이다. 모든 실제 화면 요소의 접근성을 감사한 결과는 아니다. 상태에는 글자·기호·선 모양도 함께 사용한다. 주요 일반 버튼은 진한 회색, 전송은 진한 보라를 제안한다.

## 시안 조작

- 위쪽 화면 메뉴 또는 왼쪽 레일로 시안을 전환한다.
- 설계 4개, 아키텍처 3개, 지식 그래프 2개, RAG 3개 세부 탭을 전환할 수 있다.
- 대화 켜기·끄기와 모바일 보기 전환을 제공한다. 작은 화면에서는 본문과 대화를 각각 확인한다.
- 폴더 · 문서의 편집 버튼은 임시 편집 상태를 보여준다. 검색·저장·메시지 전송·채택·실행은 실제 기능을 호출하지 않고 예시 안내만 표시한다.

## 실제 적용 순서 제안

1. 공통 색상 변수와 `color-scheme`, 레일·버튼·입력창을 맞춘다.
2. 대시보드·설계·대화·개요에 적용해 자주 보는 화면의 기준을 잡는다.
3. 아키텍처·구현·테스트·지식 그래프·RAG·문서·기록·기획 문서·배치도에 적용한다.
4. 팝업·호버·키보드 초점·비활성·빈 화면·충돌과 작은 화면을 확인한다.

현재 `console.css`에는 대화 입력 영역, 활동 달력, Log 등에 고정된 어두운 색이 남아 있다. `requirements.css`·`semantic.css`·`rag.css`도 색을 개별 지정하고 있어 공통 변수 전환과 화면별 정리가 함께 필요하다. 그래프의 노드·선·조작 도구와 코드 표시의 문법 색도 같이 확인한다. 외부 앱을 띄운 iframe의 테마는 해당 앱 설정을 따른다.

시안 방향이 정해지면 위 순서로 제품에 적용한다. 이번 작업은 시안 제시까지다.

## 확인

- Chrome에서 주요 화면 14개와 세부 탭 12개 전환 확인.
- 모바일 390px에서 대시보드·설계·RAG·대화 확인.
- 대화 표시 토글과 문서 임시 편집 상태 확인.
- 페이지 실행 오류 0건, 검사 대상의 페이지 가로 넘침 0건. 그래프와 긴 표의 내부 스크롤은 허용한다.
- JavaScript 구문 검사 통과. 결과는 `validation.json`에 저장했다.
- 독립 시안 변경으로 제품 시험은 추가하거나 실행하지 않았다.
