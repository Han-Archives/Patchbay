# 흐름도 세부 항목 트리 표 구현 · 2026-10-15

요청: [시안](흐름도-트리표-태그색_20261015_v1.md) 그대로 실제 대시보드에 구현하되 흐름도는 그대로 둔다.

## 반영

- 흐름도 `ProjectCycleFlow.tsx`는 바꾸지 않았다. 그 아래 `CycleTaskTable.tsx`를 시안의 트리 표로 교체(이전 1~3안 비교 화면 · 검색 · 남은 작업만 거르기는 뺐다). 상단 「설계 열기 ↗」 같은 단계 이동 버튼은 남겼다.
- 열: 번호(작업 01 · 세부 1.1) · 항목명(7글자 뒤 「...」, 마우스를 올리면 전체) · 상태(같은 자리 · 같은 너비, 대기 회색 · 진행 보라 · 완료 초록) · 설명 · 태그(UI · Agent · 데이터 · 서버 · 문서, 세부 행 왼쪽 색 띠, 작업 행은 태그별 개수) · 실행(아이콘만).
- 실행 아이콘: ▶ 할일로 · 목록 아이콘 = 할일에 있음(누르면 할일에서 빼기) · 실행 중에는 목록 아이콘만 · ✓ 완료 · − 빼기(이미 올린 할일은 남김).
- 상태는 저장하지 않는다. 연결 할일이 없으면 대기, 할일이 끝났으면 완료, 그 할일의 대화가 실제로 실행 중이면 진행. 진행 중인 세부 항목만 번호 앞 불빛이 깜빡인다(동작 줄이기 설정이면 고정). 작업 행 상태는 세부에서 모으고 PRD · 노드 기준 완료도 따른다. 3초마다 다시 조회.
- 저장: 작업 공간 `projects/<alias>/cycle-items.json`(`cycleItemStore.ts`, 프로젝트별 직렬화). API `GET /api/cycle-items` · `POST /api/cycle-items/action`(add · del · play · unplay, `cycleItemActions.ts`). play는 `todos.json` 맨 아래에 할일(제목 = 항목명, 설명 = 설명 + 「흐름도 · 단계 › 작업」)을 만들고 `todoId`로 잇는다.
- LLM 계획: 실제 작업 차례의 Claude · Codex 지시문(`roomHost.ts`의 할일 지시 뒤)에 파일 경로 · 형식 · 규칙을 넣었다. 쓰기 범위는 이미 `todos.json` 폴더 전체라 따로 열지 않았다. 흐름도에 없는 작업 이름으로 계획된 항목은 표 맨 아래 작업으로 보인다.
- 실제 대시보드 카드가 시안보다 좁아(약 545px) 열 너비를 줄였고, `.main-shell button`의 44px 최소 높이를 표 안 원형 아이콘에는 쓰지 않게 했다. 휴대폰 폭에서는 표가 카드 안에서 가로로 스크롤된다.

## 검증

- Core 빌드, Flow 형검사 · 빌드 통과. 시험: 새 세부 항목 저장 3개 · 동작 5개 포함 Core 525 · Flow 400 모두 통과.
- 임시 작업 공간(`PATCHBAY_HOME` 스크래치, 예시 프로젝트 demo, 포트 4399)에서 실제 빌드 콘솔을 열어 확인: 행 펼침, ▶ → 할일 API에 추가 · 아이콘 바뀜, 아이콘 다시 누르면 할일에서 빠짐, + 네 칸 입력 · 포커스 · 추가(태그 색 띠), − 빼기, 흐름도 캔버스 그대로, 콘솔 오류 없음. [데스크톱](흐름도-트리표-구현_20261015_v1/desktop.png) · [모바일](흐름도-트리표-구현_20261015_v1/mobile.png).
- 확인하지 못한 것: 실제 LLM 실행 중 불빛. 진행 상태 계산은 시험으로 확인했고, 화면은 그 상태일 때 불빛 요소를 그린다. 실제 대화 실행으로 켜지는 모습은 보지 못했다.
- 사용 중인 4318 콘솔은 옛 빌드로 떠 있어 재시작하지 않았다.
