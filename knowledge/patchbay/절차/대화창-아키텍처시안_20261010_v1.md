# 대화창 아키텍처 시안 · 2026-10-10

상태: 구현 전 디자인 제안. 사용자 정정에 따라 같은 시안 파일을 상담·실행 분리 구조로 수정했다. 제품 코드 변경은 없다. 최신 책임 분리는 `대화창-상담실행분리_20261010_v1.md`를 따른다.

## 디자인 판단

상담(요구 판단·Plan), 테스트 실행(Act·Check·Deploy), 공급자 호출을 세 영역으로 배치했다. 상담→PRD 검토·채택→승인본 구현 연결→LangGraph 실행의 기존 흐름을 반영한다. 상담과 테스트·실행 기록은 별도 저장하고 승인본 버전·출처로 연결한다. 하단의 조회·알림은 원본별 권한을 검사해 분리 표시한다. 상담 품질 평가·개선의 독립 경로와 테스트 피드백 연결도 그렸다. 구현 후 실제 배치도는 기존 XYFlow/boardCanvas 기반으로 표현할 수 있는 구조다. 이번 산출물은 별도 런타임을 설치하지 않는 SVG/HTML 시안이다.

프로세스는 상담·Plan → 채택 → 실행 준비 → Act → Check → Deploy. Check의 구현 오류는 Act로, 요구 변경은 상담으로 돌아간다. 실행 준비는 승인 범위 내 모델 추천·작업 배정이며 요구사항의 Plan을 다시 결정하지 않는다. 단계 이동 버튼은 시안 탐색이며 실제 상태 전이나 배포를 수행하지 않는다.

테스트 대화창은 Plan을 상담 채택본의 읽기 전용 참조로 표시한다. 가운데에는 승인본·작업·근거, 오른쪽에는 실행 요청·테스트 리더 배분·작업자 결과·검토를 보여 준다. 요구 변경은 상담 이동 흐름으로 연결한다. 수치·로그인 사례·공급자 역할은 모두 가상이며 모델 품질 검증 결과가 아니다.

PC·모바일 웹은 전체 기록, Claude/Codex는 연결된 MCP를 통한 조회, Discord/Telegram은 요약 알림과 원문 링크로 표현했다. 최초 범위는 컴퓨터와 서버가 켜진 동안이다.

## 확인

- SVG XML 구문·marker 연결·중복 id 확인 통과.
- HTML 내 스크립트를 추출해 Node DOM 대역으로 탭·키보드 이동, 6단계 이동, Check 구현 오류 → Act, 요구 변경 → 상담, Check 통과 → Deploy, 테스트 대화창 → 상담 흐름, 처음부터 보기 확인 통과. HTML id·접근성 참조도 확인했다.
- 브라우저의 실제 픽셀 렌더링과 모바일 실기기 검증은 수행하지 않았다. 900px 이하 레이아웃과 키보드 탭 탐색을 제공한다.
- 실제 모델 호출·메시지 전송·배포 없음. 기존 코드 및 미커밋 변경 보존.
