## 다섯 번째 탭을 만들지 않았다

기획서 §6이 「다섯 번째 탭」을 금지한다. 설계 화면은 **프로젝트 탭의 세 번째 세그먼트**다 —
개발 · 구조 · **설계**. 구조 세그먼트가 이미 같은 방식으로 들어가 있어서 자리가 있었다.

세그먼트는 IR이 없어도 보인다. 없을 때 감추면 **1단계 미착수가 「기능이 없다」로 보인다** —
화면이 「아직 설계가 없다」고 말하는 편이 사실에 가깝다.

## 통과 조건 셋 — 실물 확인

**1. 화면만 보고 어느 칸이 막혔고 무엇을 고칠지 안다.**

```
1.0=pass 1.1=pass 1.2=fail 1.3=pass 1.4=pass 1.5=invalid 1.6=invalid 1.7=pass 1.8=pass 1.9=fail
막는 이유: 검사가 막는다 — 돌아갈 칸: 1.2
```

**막힌 칸(`fail`)과 무효가 된 칸(`invalid`)을 구분한다.** 둘은 다른 일을 요구한다 —
하나는 「여기를 고쳐라」, 다른 하나는 「저기를 고친 뒤 여기를 다시 확인해라」다.
칸마다 「고치는 곳」(`caps · tools · models` 같은)을 달아 뒀다.

**2. 승인 전 초안이 현재 IR을 덮지 않는다.**

```
$ POST /api/ir/adopt   (초안이 통과할 때)   → {"ok":true,"version":1}
$ POST /api/ir/adopt   (models[] 를 비운 뒤) → HTTP 409
  "설계 규칙 검사를 통과하지 못했다 — 돌아갈 칸: 1.2 (같이 무효: 1.5 · 1.6)"
$ GET  /api/ir?source=current                → 승인 버전 1 · 통과 True
```

**3. State 변경 시 무효 상태가 즉시 보인다.** `ir.proposed.yaml`이 워치에 없어서
초안을 고쳐도 화면이 그대로였다. 워치에 넣었다.

## 설계 판단 넷

**1. 화면이 자기 쓰기 경로를 갖지 않는다.** 채택 버튼은 Core의 `adoptIr`를 부르고,
`patchbay ir adopt`도 같은 함수를 부른다(원칙 8). 순서는 **검사 → 보관 → 교체**이고,
보관이 실패하면 교체하지 않는다 — v(n)을 v(n+1) 자리 만들자고 잃지 않는다.

**2. SSE 이벤트 이름을 다섯으로 늘리지 않았다.** 넷(`progress`·`inferred`·`overlay`·`board`)은
아키텍처가 고정한 값이다. `ir.proposed.yaml`은 `overlay`로 보고한다 — 둘 다 그 프로젝트가
**손으로 쓴 설계 상태**이고, 소비자가 할 일도 같다(다시 읽는다). 보관본(`versions/1/ir.yaml`)은
이벤트가 아니다. 바뀌지 않는 파일이다.

**3. 새 그래프 기반 시설을 만들지 않았다.** 1.5의 회로는 흐름 탭이 쓰는 `layout()`(Kahn 랭크)과
XYFlow를 그대로 쓴다. `__start__`·`__end__`를 함께 그린다 — 도달성 검사가 재는 대상이 안 보이면
「끝으로 갈 수 없는 노드」가 왜 실패인지 화면에서 알 수 없다.

**4. 표는 목록 자체가 핵심일 때만.** 권한 계단 · State · 문서 의존 · 추적 표는 표이고,
노드와 엣지는 그래프다. State 표에는 **쓰는 노드 / 읽는 노드**를 같이 뒀다 —
1.4와 1.5의 어긋남이 그 두 칸에서 보인다.

## `ir adopt` — 유일한 쓰기 경로

```
$ patchbay ir adopt --project <alias>
  (승인된 IR이 이미 있으면) 차이를 먼저 출력하고 --yes 없이는 멈춘다
  검사 실패 → exit 1. **--force 는 없다**
  성공 → versions/<n>/ 에 이전 판 보관, 버전 +1, 초안은 그대로
```

버전 번호는 **커널이 센다.** 초안이 주장하는 값을 믿지 않는다 — 초안은 제안이고 둘이 각각
「v2」라고 주장할 수 있다. 실제로 무엇이 v2가 됐는지는 채택 시점에 기록되는 사실이다.

## 남은 것

`ir diff`는 CLI에만 있다. 화면은 「승인된 판과의 차이」를 절별 개수로 보여 주지만,
**무엇이 어떻게 달라졌는지 줄 단위로는 안 보여 준다.** 채택 전에 그게 필요하면 M6의 버전 비교와
같이 만드는 편이 낫다 — 그쪽이 v(n)↔v(n+1) 비교를 이미 요구한다.
