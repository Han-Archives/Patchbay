# 대화 안 문서 이미지·사진 표시 확인과 보완

작성일: 2026-10-30 (Asia/Seoul)

사용자 요청: 대화창에 문서 이미지나 사진이 바로 나오기를 원하며, 그 기능이 동작하는지 확인해 달라는 요청.

확인 결과: 설계 상담에 첨부한 이미지는 기존 썸네일이 있었지만, 일반 대화의 `ChatText`는 이미지 경로와 마크다운 이미지를 링크·문자열로만 표시했다. 일반 대화의 파일 선택도 텍스트 문서만 받았다.

## 변경

- `chatLinks.ts`에서 마크다운 이미지·링크와 이미지 확장자를 구분한다. 한글·공백 경로와 쿼리 있는 URL을 지원하며 코드 울타리 안 예시는 이미지로 바꾸지 않는다.
- `ChatText.tsx`에서 PNG·JPG/JPEG·GIF·WebP·SVG 경로, 이미지 URL, `![설명](주소)`를 메시지 안에 표시한다. 크기는 메시지 폭과 최대 높이에 맞추고 지연 로딩한다. 누르면 원본을 열고 프로젝트 파일과 첨부에는 받기를 제공한다.
- 이미지 로드 실패 시 안내와 원본 링크를 남긴다. HTTP(S), 프로젝트 파일과 해당 프로젝트의 첨부 주소를 사용한다. 실행 가능한 URL은 이미지로 만들지 않고 외부 요청에는 referrer를 보내지 않는다.
- 일반 대화의 첨부 메뉴를 「문서 · 사진」으로 바꿨다. 사진은 기존 `POST /api/refs/file`로 10MB까지 저장하고 기존 `GET /api/refs/raw`로 표시한다. 기존 대화 기록 API에 마크다운 이미지 참조를 남기므로 메시지 저장 형식과 API를 추가하지 않았다.
- 「프로젝트 파일」에서 이미지를 선택해도 바이너리를 글로 읽지 않고 이미지 참조를 기록한다. 사진 업로드 중에는 중복 첨부와 전송을 막는다.

이미지를 화면에 표시하는 기능이다. 모델에 이미지 픽셀을 넘기는 비전 입력 기능은 이번 변경에 포함하지 않는다. PDF·HTML 등 일반 문서는 기존 열기·받기 링크를 사용한다.

## 확인

- `ChatText`·링크 해석·첨부 HTTP·프로젝트 파일 접근 시험 29개 통과.
- Flow 형검사와 클라이언트·서버 빌드 통과.
- Chrome에서 실제 컴포넌트의 문서 이미지, JPG 이미지, 외부 이미지 링크의 로드와 원본 크기를 확인했다. 첨부 선택→업로드 요청→대화 기록 요청→미리보기 갱신을 확인했다.
- 390px 모바일에서 페이지 가로 넘침 없음, 이미지가 대화 패널 폭 안에 들어옴, 페이지 실행 오류 0건.
- 브라우저 검증에서는 업로드·기록 요청을 가로채 실제 대화와 첨부를 저장하지 않았고 모델을 호출하지 않았다. HTTP 시험은 임시 프로젝트를 사용했다.
- 실제 화면 캡처와 `validation.json`은 비공개 기록층 `workspace/records/patchbay/절차/대화-이미지표시_20261030_v1/`에 보관한다.
