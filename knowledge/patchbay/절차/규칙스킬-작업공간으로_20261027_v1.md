# 규칙 · 스킬을 도구 파일에서 Patchbay 작업 공간으로 (2026-10-27)

## 요구

Patchbay를 쓰는 프로젝트는 사용자가 지정한 규칙 · 스킬을 저장해 두고, "써줘"라고 하면 그 폴더의 규칙 · 스킬을 보고 쓴다. Cursor에 종속시키지 않는다.
결정(사용자, 추천대로): 저장 위치는 작업 공간 `projects/<alias>/`, 원본은 하나 · 도구 파일은 원할 때만 내보내기.

## 고친 것

- 커널 `core/src/studio/projectRules.ts`: `projectRulesDir` · `projectSkillsDir`, 규칙 `rules/<이름>.md`(머리말 `description` · `apply: always|request`), 스킬 `skills/<이름>/SKILL.md`(같은 이름이면 공용 `skills/`보다 앞섬), 쓰기 `writeProjectRule` · `writeProjectSkill`(임시 파일 교체), `rulesPrompt` · `pickedRules`, `exportProjectRules(cursor|claude)`. 이름은 한글 · 영문 소문자 · 숫자 · `. _ -`.
- 대화방 `roomHost.ts`: 모든 LLM(Claude · Codex · 로컬)의 프롬프트에 always 규칙 본문과 나머지 목록, 말에 이름이 나온 규칙 · 스킬은 본문까지. 파일을 못 읽는 LLM도 받는다. 사용자가 저장하라고 하면 `patchbay rule save`를 쓰도록 지시.
- MCP `get_rules`(읽기 전용) · `save_rule`, 세션 안내 4번에 "get_rules로 읽고 always를 따른다".
- CLI `patchbay rule list|show|save|export --project <alias>`.
- 콘솔: `GET /api/rules`, 입력칸 「+ → 규칙 · 스킬」(고르면 「이름」만 넣고, 보내면 서버가 본문을 넘김). 「폴더 · 문서」 편집기에 `rules/` · `skills/` 설명.
- Patchbay 자기 규칙 8개 → `workspace/projects/patchbay/rules/`(모두 always — 지금까지 CLAUDE.md가 늘 포함했던 효과를 지킴, 본문 원본과 같음 확인). 옛 `.mdc` → `archive/docs/규칙/`(portfolio-deck은 `workspace/records/archive/docs/규칙/`), `.cursor/rules` 링크 → `.trash/2026-10-27/`(MANIFEST에 되돌리는 명령).
- `CLAUDE.md` · `AGENTS.md` 머리를 새 원본 안내로, `CLAUDE.md` 맨 아래 칸은 `patchbay rule export --target claude`(레포 안 원본이면 상대 경로). `.gitignore`의 Cursor 링크 줄 삭제. `llms.txt` · `knowledge/index.md` · `규칙/README.md` · 저장구조.md(3 · 5절 · 바뀐 기록) · 아키텍처.md/.json · 개요.md.
- 할일 「Cursor 규칙 링크 걸기」 완료 처리(필요 없어짐).

## 남은 것

- 지금 열려 있는 Claude Code 세션들의 Patchbay MCP는 새 도구(get_rules)를 다시 켜야 받는다.
- 규칙 본문 안의 옛 파일 이름(`doc-versions.mdc` 등)은 그대로다 — 이름으로 알아볼 수 있어 두었다.
- 공용 스킬 `new-project`는 새 프로젝트에 CLAUDE.md · AGENTS.md · .cursor rules 초안을 쓰도록 되어 있다. 새 방식(작업 공간 규칙)으로 바꿀지는 따로 정한다.
- 공개 레포에는 이제 규칙 본문이 없다(작업 공간은 git 밖, 비공개 백업). 옛 판은 archive/docs/규칙/에 있다.
