# 개요 전환 시 Tasks 누적 수정 · 2026-10-18

요청: 원인이 확인된 Tasks 누적 현상을 수정하고 커밋한다.

## 문제와 변경

대시보드의 형제 컴포넌트 `TodoPane`와 `DashboardHistory`가 모두 `key={project}`를 써 식별자가 충돌했다. 개요 문서가 없거나 조회 중인 대체 개요로 전환하면 같은 `div`가 재사용되면서 Tasks DOM이 남고, 왕복할 때마다 패널이 누적됐다.

`app/apps/flow/src/DashboardPane.tsx`에서 다음 식별자를 분리했다.

- Tasks: `tasks:${project}`, History: `history:${project}`.
- 대시보드 컨테이너: `dashboard:${project}`.
- 문서 개요: `overview:${project}`, 대체 개요: `overview-fallback:${project}`.

전환할 때 해당 화면의 하위 컴포넌트가 정상적으로 해제·생성된다. 기존 작업 중인 다른 변경은 이번 코드 커밋에 포함하지 않는다.

## 검증

- Flow 타입 검사·프로덕션 빌드 성공.
- 관련 테스트 12개 통과: 대시보드 6, 개요 파싱 1, 화면 복귀 5.
- 실제 Chrome 7조건에서 각 5회, 총 35회 왕복 확인.

| 조건 | 개요 Tasks | 대시보드 Tasks |
| --- | --- | --- |
| 가상 프로젝트, 문서 없음(404) | 항상 0 | 항상 1 |
| 가상 프로젝트, 조회 실패(503) | 항상 0 | 항상 1 |
| 가상 프로젝트, 문서 정상 | 항상 0 | 항상 1 |
| 가상 프로젝트, 1초 지연 조회 중 새로고침·전환 | 전환 직후·응답 후 모두 0 | 항상 1 |
| 가상 프로젝트, 모바일 390px·문서 없음 | 항상 0 | 항상 1 |
| 4318, 진단 브라우저에서만 문서 없음으로 응답 | 항상 0 | 항상 1 |
| 4318, 정상 문서 응답 | 항상 0 | 항상 1 |

메뉴를 연 뒤 전환해도 남는 Tasks 메뉴가 없었다. 개요에 머물며 3.4초 관찰했을 때 해제된 Tasks의 3초 주기 조회도 0회였다. 가상 프로젝트의 저장 할일은 누락된 `inactive` 기본값을 false로 정규화해 비교했으며, 내용·순서·상태·건수가 유지됐다. 최초 검증기의 비교는 생략값과 false 차이를 실패로 판단했으므로 이 비교만 보완해 재실행했다.

브라우저 실행 오류 0, 모델 호출 0회. 실서버에서는 API 쓰기 요청을 가로채 차단했다. 새 빌드 파일은 현재 4318 서버가 제공하며, 서버 재시작 없이 새 페이지에서 확인했다. 사용 중인 기존 브라우저는 새로고침하면 적용된다.
