## 3판이 친화적이지 않았던 이유

1. 설계 칸 순서(0.0 → 1.8)로 묻는다 — 사람의 생각 순서가 아니다
2. 전문 형식(관계 개수 행렬 · MoSCoW · EARS · 역량 질문)을 그대로 낸다
3. 사람이 모르는 것(기다리는 시간 · 되돌리기 · 일하는 방식)을 묻는다
4. 요구를 먼저 듣지 않아 질문을 맞출 수 없다 — 고정 선택지가 아이디어를 가둔다
5. 결과를 설계도로 보여 줘서 「내가 원한 건가」를 판단할 글이 없다

## 안

- Phase 1~9 + 바탕(0.0)을 **하위 칸 48개**로 나누고, 칸마다 「빠지면 생기는 일」을 적었다.
  누가 채우나: **묻기 20 · 해석 20 · 기본값 8**.
- 사람에게는 **장면 질문 7묶음 22문항**(A 하고 싶은 일 · B 쓰는 장면 · C 예시 세 개 · D 잘못될 때 ·
  E 맡기는 범위 · F 보는 자료 · G 잘 됐다는 기준). C 예시가 내놓는 것 · 갈래 · 완료 조건 · 시험을 함께 만든다.
- 흐름: 요구 한두 문장 → 호스트 모델이 문항 틀을 그 사람 낱말로 맞춤 → 답 → 호스트 모델이 하위 칸에 해석
  → Patchbay가 검사 + IR에서 PRD를 결정적으로 그림(문장마다 묻기/해석/기본값 출처) → 절마다
  「맞아요 / 고쳐 주세요」 → 고친 절의 Phase만 무효 전파(명세 20260929a §7.3)대로 다시 해석.
- 커널은 모델을 부르지 않는다(원칙 5·9). 맞춤·해석은 10-05 대화 요청 길(thread_id · `answer_request`).

## 정할 것 (추천 먼저)

1. 맞춤·해석 주체 — 호스트 모델 / 결정적 규칙만
2. PRD 고치는 방식 — 절마다 맞아요·고쳐 주세요 / PRD 글 직접 고치기
3. 설문 3판 — 「자세히 묻기」로 남김 / 걷어 냄
4. PRD 검토 자리 — 콘솔 1 설계 화면 / Claude Docs 댓글

## 이어서 — 추천대로 갔을 때 LangGraph · 뒤 단계 점검 (같은 날)

요구: 「추천대로 진행했을 때 LangGraph와 연동하거나 이후 작업 진행하는데 문제 없는지 확인」. 코드를 읽어 확인했다.

**고치고 가야 할 것 3**
1. 상담은 지금 대화 길을 그대로 못 탄다 — `sendThreadMessage`가 assistantId와 LangGraph 연결을 요구하고, `answerRequest`는
   그래프의 `waiting` 줄에만 답을 붙이고, `resumeReady`가 답 붙은 대화를 LangGraph로 재개한다. 1단계엔 그래프가 없다.
   → 상담 전용 대화 갈래(LangGraph를 타지 않음, 재개 대상에서 빠짐). 저장 형식 · MCP 답 길은 그대로 쓴다.
2. 호스트는 스스로 깨지 않는다 — 지금은 턴마다 「호스트에게 줄 한 줄 복사」. 상담 수십 턴은 못 견딘다.
   → MCP 기다리기 도구(다음 말이 올 때까지 막혀 있다 돌아옴) + 호스트 쪽 반복 안내. 모델 「선택」은 강제가 아니라 이름표 + 걸러 받기.
3. IR 새 칸은 스키마에 넣지 않으면 조용히 사라진다 — zod 기본이 모르는 키를 버리고, `adoptIr`이 파싱한 값을 쓴다(`irStore.ts:257`).
   → schemaVersion 3 + 선택 칸.

**설계로 풀리는 것**: 환경 · UI를 새 Phase로 만들지 않고 1.2 · 1.1 아래에 둔다(`IR_GATES` · 무효 전파 · 레일 그대로) /
뼈대는 TS만(`generate.ts` → `@langchain/langgraph` JS) — 언어 칸은 typescript만, 검사로 막음 / LangGraph 주소는 콘솔에 하나
(`PATCHBAY_LANGGRAPH_URL`) — 원격 프로젝트는 SSH 터널 / `EMIT_TARGETS`에 DB 없음 — `db` 추가, 3단계 Neo4j와 섞지 않음 /
외부 MCP는 `tools` + `cap:external`로 적히지만 생성기는 자리만 만든다 / 초안 원본은 하나 — 상담으로 시작하면 3판 설문은 읽기 전용.

**문제 없음**: 예시 → `evals.test.ts` · PRD를 IR에서 그리기 · 검사 · 채택 · 2.6 어긋남 · 문서 의존 · 실행 기록.

## 이어서 — 구독형 호스트(Claude Code · Codex)에서 상담 연동이 되나 (같은 날)

요구: 「2에서 언급한 내용이 구독형 LLM(claude code와 codex)에서 연동이 되는지. 엄청 중요한 부분」.

**실측 (Claude Code 2.1.289, claude.ai 구독 로그인)**
- 턴마다 부르기: `claude -p … --session-id <uuid>` → `claude -p … --resume <uuid>` — 두 번째 턴이 첫 턴의 내용(숫자 7)을 기억했다. 구독으로 돈다.
- 기다리는 MCP 도구: 75초 막혀 있다 돌아오는 stdio 도구를 `--mcp-config`로 붙여 불렀다 — 82초 뒤 정상 답(「42」). CLI는 60초에 끊지 않는다.

**문서로 확인 (Codex — 이 컴퓨터에 설치돼 있지 않아 실측 못 함)**
- `codex exec`는 ChatGPT 계정 로그인으로도 돈다. `codex exec resume <SESSION_ID>`로 이어 가고 `--json`이 JSONL을 낸다.
- MCP 도구 한도는 기본 60초, `[mcp_servers.<id>] tool_timeout_sec`로 늘린다.

**구독 사용량**: Anthropic이 6-15에 「`claude -p` · Agent SDK는 별도 월 크레딧으로」를 예고했다가 보류했다 — 지금은 구독 한도에서 빠진다. 다시 시행되면 턴마다 부르기는 별도 크레딧(Pro 월 $20 상당)을 쓴다.

**판단**: 추천을 「호스트가 기다리기 도구를 반복해 부름」에서 **「콘솔이 턴마다 호스트 CLI를 같은 세션으로 부름」**으로 바꾼다.
복사 붙이기 · 빈 기다림의 토큰 낭비 · 호스트가 반복을 멈추는 위험이 없고, 사용자가 고른 모델을 `--model`로 실제로 지정할 수 있다.
기다리기 도구는 IDE 창에서 직접 상담하고 싶을 때의 보조 길로 남긴다. 콘솔이 이미 Claude Code를 띄운다(`processHost.ts`) — 키를 들지 않고
사용자의 로그인을 쓰는 것은 같다. 상담 호스트는 읽기 전용(Claude `--allowedTools` · Codex `--sandbox read-only`)으로 부른다.
