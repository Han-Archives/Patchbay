# 요구사항 개요+초점 구현

2026-10-16 · 사용자 승인한 30개 요구사항 HTML 시안을 제품 설계 화면에 적용했다.

## 사용

왼쪽 「설계」의 기본 화면이 「요구사항」이다. 기존 기획 문서는 추가 기능의 「기획 문서」에서 연다.

- 전체·직접 변경·영향 확인·미결·검토 확정 필터, ID·내용 검색, 기능 묶음 필터
- 선택 요구사항의 왜·무엇·경계·확인·연결·미결 6칸
- 필드별 변경 전후 비교, 변경 이유, 실제 프로젝트 대화·설계 상담 원문
- 관련 흐름의 현재·초안 비교(XYFlow), 시험 계획, 검토·구현·실행 결과 구분
- 새 요구사항·수정·초안 제외, 미결 질문 편집, 대화 제목·발언 선택으로 근거 연결
- 개별·일괄 검토 확정, 보류, 되돌리기, 검토 이력
- 원문·단계·시험이 달라지면 이전 확정을 대기로 전환

개별 검토 확정은 판 전체의 채택이 아니다. 기존 PRD 검토·설계 검사를 유지하며, 검토 기록이 있는 변경에 미확정·보류가 남으면 화면의 판 채택을 막는다.

기존 문장과 ID를 보존한다. 저장된 설계가 없는 프로젝트는 빈 상태로 안내하며 예시 데이터로 채우지 않는다. 실제 설계 요구사항은 새 요구사항 또는 설계 상담으로 작성한다. 과거 대화 기록은 보존한다.

## 구조

- Flow: RequirementsPane.tsx, requirements.css, requirementView.ts; App.tsx, ProjectTools.tsx 연결
- HTTP: GET /api/requirements, GET /api/requirements/evidence, POST /api/requirements/edit, POST /api/requirements/review
- Core: ir/requirements.ts, ir/valueDigest.ts; 요구사항 선택 필드와 상담 지시 확장
- 저장: 기존 ir.proposed.yaml + ir.requirement-review.json. 검토 파일은 잠금·임시 교체로 저장한다. 편집은 문서 지문을 확인하고 상담 쓰기와 같은 잠금을 사용한다.
- 이벤트: 검토 파일 변경은 기존 overlay SSE로 알린다.
- 객체 키 순서가 달라진 것만으로 요구사항이 바뀐 것으로 판정하지 않는다.
