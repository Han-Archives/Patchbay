# 콘솔 화면에서 서버 다시 켜기 (2026-10-26)

## 요청과 결정

콘솔 화면에서도 서버를 다시 켤 수 있는지 검토. 서버를 지켜보는 쪽(launchd 등)이 없어서 서버가 자기 자신을 다시 켤 수는 없다. 세 안(A 서버가 교대 · B launchd · C 안 넣음)을 비교한 페이지를 보이고, 사용자가 **A. 서버가 교대**를 골랐다.

## 동작

1. 레일 아래 「↻ RS」 → 체력바와 같은 팝오버에서 「빌드하고 다시 켜기」 / 「그냥 다시 켜기」 / 「닫기」.
2. `POST /api/server/restart` `{ build }` — LLM이 일하는 중(대화 · 상담 · 실행 · 사전 준비 · 지식 · RAG)이면 409와 프로젝트 이름. 빌드를 고르면 앱 루트 `npm run build`(core · cli · mcp · skills) → `apps/flow` `npm run build`. 실패하면 500과 출력 끝 2000자, 서버는 끄지 않는다. 빌드 뒤 한 번 더 일하는 중인지 본다.
3. 통과하면 202. 지금 서버가 같은 명령 · 환경(`PATCHBAY_FLOW_RESTARTED=1` 추가, `--no-open`)으로 새 서버를 띄우고(분리 · 같은 출력) 정리 뒤 꺼진다.
4. 새 서버는 포트가 비어 있지 않으면 250ms마다 다시 시도(최대 15초).
5. 화면은 `GET /api/server`의 `pid`가 바뀌면 새로고침. 60초 안에 안 바뀌면 터미널에서 확인하라고 알린다.
6. 조회 전용 연결이거나 `serve.ts`가 아닌 실행(시험 · 임시 앱)이면 버튼이 없다(`canRestart`).

| 파일 | 내용 |
|---|---|
| `app/apps/flow/src/server.ts` | `ServerRestart` 옵션, `GET /api/server`, `POST /api/server/restart` |
| `app/apps/flow/src/serve.ts` | 실제 빌드 · 교대, 포트 재시도 |
| `app/apps/flow/src/ServerRestartRail.tsx` | 레일 버튼 · 팝오버 · 새로고침 |
| `app/apps/flow/src/serverRestart.test.ts` | 501 · 빌드 실패면 안 끔 · 202 뒤 교대 · 중복 409 · 일하는 중 409 |

## 확인

- 전체 시험 1339 통과 · 3 건너뜀, 빌드 통과.
- 실제 콘솔(4318)에서 「빌드하고 다시 켜기」: 빌드 5초, 교대 1초, pid 42682 → 42925, 옛 프로세스 종료, 로그는 같은 파일로 이어짐.
- 화면 캡처로 레일 버튼과 팝오버 확인.

## 대가 (A안)

- `patchbay flow`로 터미널에서 띄운 서버를 화면에서 다시 켜면, 새 서버는 터미널과 분리된다(출력은 같은 곳으로 가지만 Ctrl+C로는 안 꺼진다).
- 새 서버가 못 뜨면(빌드 없이 깨진 코드로 다시 켜기 등) 터미널에서 직접 켜야 한다.
