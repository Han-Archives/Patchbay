# 설계 화면을 Phase 프로세스로 · 2026-10-01

| 항목 | 값 |
| --- | --- |
| 요구 | 「1.0~1.9를 Phase 1~9로 하고 위에서 아래 순서 프로세스로 보여 주고, 사용자가 누르면 해당 창이 프로세스 아래에 보이게」 |
| 바뀐 곳 | 프로젝트 탭 · 설계 세그먼트 — 진행 중 화면과 판정 화면 **둘 다** |
| 검증 | **811 테스트 / 94파일** · 콘솔에서 `practice` 로 두 화면을 걸었다 |

## 번호를 어떻게 맞췄나

칸은 열 개(1.0~1.9)이고 Phase는 아홉이다. 그래서:

| 명세 칸 | 화면 |
| --- | --- |
| 1.0 ~ 1.8 | **Phase 1 ~ 9** (1:1) |
| 1.9 설계 규칙 검사 | **최종 검사** — 프로세스 맨 아래. 내용을 적는 칸이 아니라 아홉 Phase를 판정하는 칸이다 |

Phase 옆에 칸 번호를 작게 같이 적는다. 검사 id(`1.2/model-declared`)와 CLI 출력은 칸 번호를 쓰므로
사람이 화면과 맞춰 볼 수 있어야 한다. 이름은 `docs/용어.md` 「새로 들인 이름」에 올렸다.

## 화면

```
Phase ─ 1단계 안의 아홉 칸. 위에서 아래로 채우고, 누르면 그 칸의 창이 아래에 열린다.
 (1) Phase 1  에이전트가 필요한가  1.0        적었음
  │
 (2) Phase 2  목적과 완료 조건     1.1        적었음
  ┆                                          ← 일부만 적은 칸에서 선이 끊긴다
 (✓) 최종 검사 설계 규칙 검사       1.9        8 / 9 다 적음
┌ Phase 9  eval + 추적 표  1.8 ──────── [닫기] [이 칸 저장] ┐
│ (그 칸의 창)                                              │
└──────────────────────────────────────────────────────────┘
```

| 상태 | 점 | 아래로 내려가는 선 |
| --- | --- | --- |
| 적었음 · 통과 | 초록 실선 | 초록 |
| 없음으로 적음 | 파랑 실선 | 파랑 |
| 일부 적음 | 초록 점선 | 끊김 |
| 막힘 | 주황 실선 | 끊김 |
| 무효 · 판정 안 함 · 잠김(최종 검사 전) | 점선 | 끊김 |

| 화면 | 누르면 아래에 열리는 창 |
| --- | --- |
| 진행 중 | 그 Phase의 편집기. 최종 검사는 「아직 IR로 읽히지 않는 이유」 |
| 판정 뒤 | 그 칸의 내용 + 그 칸의 막힌 검사. 초안이면 「이 Phase 고치기」로 편집기가 된다. 최종 검사는 전체 판정과 승인된 판과의 차이 |

## 설계 판단

1. **창은 프로세스 안이 아니라 아래에 연다** (요구 그대로). 프로세스를 접지 않으므로 창을 여는 동안에도
   어디까지 왔는지가 보인다.

2. **판정 화면도 같은 프로세스로 바꿨다.** 전에는 열 칸 띠 아래에 칸별 창(권한 계단 · State · 회로 · 문서 ·
   추적 표)이 전부 펼쳐져 있었다. 한 화면에서 진행 중엔 프로세스, 판정 뒤엔 띠면 같은 칸이 두 모양이 된다.
   전에 창이 없던 1.0 · 1.1 · 1.3 · 1.7에 읽기 창을 새로 만들었다.

3. **판정 화면에서도 고칠 수 있다 (초안일 때만).** 초안이 IR로 읽히는 순간 편집기가 사라지면, 검사에
   막힌 Phase를 고치러 파일로 나가야 했다. 승인된 판은 `ir adopt` 로만 바뀌므로(명세 §2.3) 거기엔 버튼이 없다.

4. **고른 Phase는 화면이 바뀌어도 남는다.** 마지막 칸을 저장해 진행 중 화면이 판정 화면으로 넘어가도
   그 Phase가 열린 채로 있다 — 선택을 두 화면 위(`IrPane`)에 두었다.

5. **「다 적음」과 「일부 적음」을 화면에서 가른다.** 커널의 `answered` 는 키 하나만 적어도 센다. 그대로
   보여 주니 「아홉 Phase 중 9개를 답했다」인데 채택이 막혀 있었다(Phase 9의 `evals` 가 비어서).
   프로세스는 어디서 멈췄는지를 보여 줘야 하므로 화면이 둘을 가르고, 선은 다 적은 칸에서만 잇는다.

6. 편집기가 다른 파일 이벤트로 화면이 다시 읽힐 때 쓰던 입력을 지우던 자리를 막았다 — 이제 그 칸의 값이
   바뀔 때만 입력을 되돌린다.

## 실측

```
판정 화면   Phase 1~9 통과 · 최종 검사 통과 · Phase 3 을 누르면 권한 계단이 프로세스 아래에
            Phase 6 을 누르면 회로(노드 3) · 「이 Phase 고치기」 → 기존 값이 든 편집기
진행 중     (Phase 9 의 evals 를 비우자) 「아홉 Phase 중 8개를 다 적었다 · 1개는 일부만」
            Phase 9 일부 적음(점선) · 최종 검사 8 / 9 · 열어 둔 Phase 가 그대로 남음
```

확인한 뒤 `practice` 초안은 백업본으로 되돌렸다 — 열 칸 통과 · 채택 가능 상태다.
