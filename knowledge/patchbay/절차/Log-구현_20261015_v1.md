## 만든 것

| 층 | 파일 | 하는 일 |
| --- | --- | --- |
| 커널 | `core/src/log/paths.ts` | `logPaths()` · 날짜 · 달 검사 · 시간대 날짜 · ISO 주 |
| | `config.ts` | `log/config.yaml`: 태그 낱말(흐름도 다섯 개로 시작) · 경로 glob · 낱말 규칙 · 요약 모델 · 시간대. 규칙은 목록 밖 태그를 거절한다. `setLogSummaryModel()`은 다른 설정과 주석을 남긴다 |
| | `changes.ts` | 변동 기록(D6) — 할일 · 흐름도 저장 함수가 앞뒤를 비교해 추가 · 완료 · 되돌림 · 삭제 · 고침을 `events/changes.jsonl`에 덧붙인다. 화면이 만드는 할일(`source`)은 뺀다. 기록에 실패해도 저장은 되돌리지 않는다 |
| | `collect.ts` | 원문 → 사건. 사건마다 안정된 id를 붙인다. 출처별 처리는 아래 표 |
| | `build.ts` | `buildLog()`: 범위가 걸친 달을 통째로 정리하고, 프로젝트별로 잠근다(대화방과 같은 파일 잠금). `records/<날짜>.md`(정리 시각을 넣지 않아 같은 입력이면 같은 바이트) · `index/<월>.json`(태그별 사건 수와 고유 파일 수를 따로). 확정(`confirmLogDay`, `wx`) · 확정 풀기(`events/archive/`) |
| | `summary.ts` | 로컬 요약 지시문(빈칸 틀 · 인용 자료 울타리) · `compactLogRecord()`(6천 자, 딸린 줄부터 줄임) · `checkLogSummary()`(절 · 근거 id 검사, 흔한 절 이름 바꿈 바로잡기) · `writeLogSummary()`(앞 판 보관, 머리말에 모델 · 지시문 판 · 원문 해시) |
| | `report.ts` | `draftLogReport()`: 일 · 주(ISO) · 월 보고서 바탕을 처음 한 번만 만든다(`wx`). 사람이 쓰는 칸은 비워 둔다. 끝나지 않은 기간 · 잠정인 날을 밝히고, 요약은 해시가 맞는 것만 「로컬 LLM 요약」으로 표시한다 |
| 대화방 | `rooms/types.ts` · `mirror.ts` | 말에 선택 칸 `sourceAt`을 둔다. 미러가 세션 기록에서 옮긴 말에 실제 시각을 붙인다(D7) |

| MCP | `mcp/src/tools/log.ts` | `log_build` · `log_read`(날짜 하나 또는 기간, 태그 · 종류 거르기, 200줄 · 2만 자 상한) |
| 콘솔 | `flow/src/logHost.ts` | `/api/log*` 열한 개. 요약은 LM Studio(`lms chat`)만 부르고, 프로젝트마다 한 번에 하나, 멈추기를 둔다. 요약하는 동안 기록이 바뀌면 저장하지 않는다 |
| | `ProjectLogPane.tsx` · `logContract.ts` · `console.css` | 1안 화면. 옛 `.project-log` 규칙은 지웠다 |
| | `App.tsx` · `DashboardHistory.tsx` | History에서 날짜를 고르면 「Log에서 보기」로 그날을 연다(`patchbay:open-log` 이벤트) |

`collect.ts`가 원문을 사건으로 바꾸는 방식:

| 출처 | 그날로 묶는 기준 · 처리 |
| --- | --- |
| 진행 보고 | 보고가 기록된 시각 |
| 대화방 | 방 하나의 하루치 말 묶음. 시각은 `sourceAt`을 먼저, 없으면 `at`. 사용자 말 발췌는 한 말당 120자, 방당 10개까지 넣고 LLM 답은 넣지 않는다. 범위보다 오래된 방 파일은 열지 않는다 |
| 할일 · 흐름도 | 변동 기록을 먼저 쓰고, 기록이 없던 때는 등록 · 완료 시각을 쓴다 |
| History 메모 | 사람이 고른 날짜와 태그를 그대로 쓴다 |
| git 커밋 | 등록부 `path` 레포의 작성 시각. 레포가 아니면 「수집 불가」로 남긴다 |

태그는 세 가지 규칙으로만 붙인다: 연결(흐름도 항목 → 할일 → 대화방), 경로, 낱말. LLM이 제안한 태그는 집계에 넣지 않는다.

## 검증

- **검사:**
  - core 546개 통과 (Log 11개, 미러 `sourceAt` 1개 추가)
  - CLI 113개, MCP 57개 통과 (`log_build` · `log_read` 1개 추가, 도구 목록 갱신)
  - flow 421개 중 420개 통과. 새 Log API 검사 3개도 여기에 들어 있다. 실패 1개는 `access.test.ts`로, 할일 사전 준비 작업 쪽의 기존 실패(`등록된 프로젝트가 아닙니다`)다
- **검사가 다룬 경우:**
  - 같은 입력이면 같은 바이트, 빈 날 · 오지 않은 날은 파일 없음
  - 변동 다섯 종류
  - 늦게 옮긴 말은 말한 날로
  - 흐름도 태그 물려받기
  - 확정한 날은 원문이 바뀌어도 그대로, 풀면 다시 잠정
  - git 아님, 두 프로젝트 격리, 동시 정리 셋
  - 보고서는 처음만 만들고 덮지 않음, ISO 주가 해를 넘는 경우
  - 요약의 가짜 근거 id · 빠진 절 거절, 원문이 바뀌면 낡음, 실패하면 앞 요약 유지
  - 조회 전용 연결은 서버 앞단에서 POST를 막으므로 쓰기 버튼도 막힌다
- **실물 (patchbay, 2026-10):** `patchbay log build`로 13일치를 0.2초에 정리했다. 콘솔 4318에서 일 · 주 보기와 요약 탭(모델 고르기)을 Playwright로 확인했고 화면 오류는 없었다.
- **빌드 중 잡은 것:** 콘솔 화면이 커널을 번들하기 때문에, `collect.ts` 맨 위의 `promisify(execFile)`가 브라우저에서 터져 빈 화면이 됐다 → 부를 때 감싸도록 고쳤다.
- **로컬 모델 실측 (qwen2.5-14b-instruct-mlx, 설정 저장 없이):**
  - 1,947자 기록: 114초. 절 이름을 「한 눈에」로 바꿔 써서 검사에 걸렸다
  - 7,307자 기록: 280초 안에 끝나지 않았다. 끊은 뒤에도 LM Studio가 몇 분 더 생성했다
  - 고친 것: 빈칸 틀 지시, 절 이름 바로잡기, 입력 6천 자 압축 → 같은 7,307자 날이 4,141자로 줄어 64초에 검사를 통과했다

## 알려진 한계

- 변동 기록은 오늘부터만 있다. 그 전의 할일 삭제 · 고침은 복원할 수 없다(원문에 시각이 없다).
- 커밋 안 된 파일은 「조회 시점 작업 트리 상태」로만 보인다. 오늘 바뀐 것이라는 뜻이 아니다.
- `GET /api/log`는 화면을 열 때 그 달을 정리한다(파생 파일 쓰기). 조회 전용 연결도 이 정리는 일으킨다.
- 14B 로컬 모델은 사건이 많은 날에 1~4분 걸린다. 기본 시간 한도는 240초(`config.yaml` `summary.timeoutMs`)다.
- 요약 품질(어느 절에 무엇을 넣는지)은 모델에 달려 있다. 근거 id가 기록에 있는지만 검사하고, 문장이 그 근거와 맞는지는 검사하지 못한다.
- 지금 돌고 있는 Claude Code의 Patchbay MCP는 다시 띄워야 `log_build` · `log_read`가 보인다.
