# 인터페이스 걷기 1 — 1단계를 화면에서 시작할 수 없었다 · 2026-09-30

| 항목 | 값 |
| --- | --- |
| 방법 | 사용자가 콘솔을 켠 순간부터 실제 화면·응답을 따라 걷는다 |
| 찾은 것 | 막히는 지점 셋. **전부 같은 모양** — 보여주기는 하고 시작하기가 없다 |
| 고친 것 | 그중 2번 (1단계 시작) |
| 검증 | **792 테스트 / 93파일** (전 776 / 91) |

## 걸으면서 찾은 것

| # | 어디 | 화면이 말하던 것 | 막히던 것 |
| --- | --- | --- | --- |
| 1 | 콘솔 첫 화면 | 「터미널에서 `patchbay project add` 를 실행한 뒤 이 페이지를 다시 열면 됩니다」 | 프로젝트 등록·스캔 라우트가 **0건**. 시작부터 터미널로 나간다 |
| 2 | 프로젝트 탭 · 설계 | 「호스트 모델이 `ir.proposed.yaml` 에 초안을 쓰면 여기에 열 칸이 뜬다」 | **1단계를 시작할 수단이 없다.** 파일이 생길 때까지 구경만 한다 |
| 3 | 같은 곳 (초안이 안 읽힐 때) | zod 오류 한 덩어리 | **다음에 뭘 하라는 말이 없다.** `missing` 엔 안내가 있는데 `broken` 엔 없었다 |

M3을 「확인 화면」으로 만들었고 그 범위 안에서는 맞다. 다만 사용자가 인터페이스에서 출발하려면
**여기가 입구**여야 하는데 입구가 없었다.

## 고친 것 — 2번, 그리고 3번의 절반

**진짜 문제는 「시작 버튼이 없다」보다 깊었다.** 열 칸을 채우는 **1단계 내내 초안은 불완전하다.**
그런데 화면은 완성된 IR만 읽을 수 있었다 — 즉 1단계를 하는 동안은 화면이 계속 쓸모없었다.
그래서 둘을 같이 넣었다.

| 무엇 | 어디 |
| --- | --- |
| 빈 골격 만들기 | `core/src/ir/draft.ts` · `renderIrSkeleton` |
| `parseIr` 없이 칸별 상태 읽기 | 같은 파일 · `draftProgress` |
| 초안 쓰기 (있으면 거절) | `core/src/studio/irStore.ts` · `startIrDraft` |
| 새 화면 상태 | `irContract.ts` · `IrViewDrafting` |
| 버튼과 진행 화면 | `IrPane.tsx` · `POST /api/ir/draft` |

```
설계 없음        → 「1단계 시작」 버튼
  ↓ 누르면
1단계 진행 중    → 아홉 칸이 빈 채로 뜬다
                   1.1 목적과 완료 조건   아직: goal · done
                   1.2 권한 경계        아직: caps · tools · models
                   …
  ↓ 채우면
                   1.1 목적과 완료 조건   적었음
                   1.2 권한 경계        없음으로 적음   아직: caps · models
```

## 설계 판단

1. **골격은 값을 지어내지 않는다.** 키는 두고 값은 비운다. 키를 두는 것은 고쳐 쓸 파일이라서고,
   값을 안 넣는 것은 자리를 채우는 기본값이 **「안 쓴 것」과 「쓴 것」을 같아 보이게** 하기
   때문이다. 그래서 골격은 `parseIr` 를 통과하지 않는다 — 통과해야 하는 것은 다 채운 뒤다.

2. **「없음으로 적음」과 「아직」을 나눈다.** `tools: []` 는 「없는 것이 답이다」이고 빈 키는
   「아직 안 썼다」다. 실행 기록의 「빈 배열은 값이다」(명세 §5.2)와 **같은 축**이다. 합치면
   `tools: []` 를 적어 넣은 사람이 안 적은 사람과 같아 보인다.

3. **있는 초안을 덮지 않는다** (409). 초안은 사람과 호스트 모델의 저작물이고, 「시작」 버튼이
   그것을 지울 수 있으면 한 번의 오조작으로 1단계가 통째로 날아간다. `wx` 플래그로 검사와 쓰기
   사이의 틈까지 막았다.

4. **깨진 초안과 깨진 승인본을 나눈다.** 초안이 안 읽히는 것은 1단계 중의 **정상 상태**라
   `drafting` 으로 「어디까지 왔나」를 말한다. 승인된 `overlay.ir` 이 안 읽히는 것은 통과했던
   것이 깨진 것이라 `broken` 으로 남기고 보관본 자리를 가리킨다.

5. **콘솔이 자기 쓰기 경로를 갖지 않는다** (원칙 8). `startIrDraft` 는 Core에 있고 화면은 그것을
   부른다. 초안에 쓰는 것이라 `overlay.ir` 의 단일 쓰기 경로(명세 §2.3)는 그대로다.

## 걷다가 잡은 것

커널 `dist` 가 낡아서 화면이 **빈 키를 하나도 못 짚었다**(`아직: -`). 단위 시험은 소스를 보고
통과하는데 콘솔은 `dist` 를 본다 — **실제로 걸어보지 않았으면 초록으로 넘어갔을 자리다.**
