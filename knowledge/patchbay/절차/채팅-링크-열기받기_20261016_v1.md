# 대화방 · 상담 창 링크 열기 · 받기 · 2026-10-16

요청: Patchbay 채팅창에서 디자인 시안이나 산출물을 링크로 보거나 받을 수 없다 — 확인해 보니 맞았다(대화방은 글을 그대로 찍고, 상담 창은 `**굵게**`만 처리, 서버에는 프로젝트 파일을 그대로 내주는 길이 없었다). 대화방 · 상담 창 둘 다, 링크와 받기까지.

## 반영

- `chatLinks.ts`: 글에서 웹 주소와 산출물 경로를 찾는다. 경로는 `/` 가 하나는 있고 html · png · jpg · gif · webp · svg · pdf · md · txt · json · csv · yaml · pptx · docx · xlsx · zip · mp4 · webm · mov 로 끝나야 한다(코드 파일 · `README.md` 같은 맨 이름은 링크하지 않는다). 백틱 안은 공백 든 경로도 받는다. 「…html에」처럼 붙은 조사는 떼고, 주소 끝 구두점 · 닫는 괄호도 뗀다.
- `ChatText.tsx`: 주소는 새 탭, 경로는 「열기」(새 탭) + 「받기」 칩. 대화방 `RoomLine` 의 모든 글과 상담 창의 내 글 · 상담자 답(굵게 유지)에 쓴다. 상담 첨부 파일은 이름이 열기, 옆에 받기, 이미지 썸네일은 누르면 새 탭.
- 서버 `GET /api/project-file/<alias>/<경로>`(`?download=1` 이면 받기): `loadProjectFile`(`sourceFileView.ts`) — 프로젝트 루트 한정(실경로까지) · L4 비밀 403 · 50MB · 폴더 400. 경로를 URL 길에 두어 시안 HTML 의 `style.css` 같은 옆 파일 참조가 그대로 풀린다. 답에 적힌 절대 경로는 프로젝트 안이면 상대 주소로 302.
- 보안: 응답마다 `CSP: sandbox allow-scripts allow-popups allow-forms allow-modals`(allow-same-origin 없음). 시안의 스크립트는 돌지만 콘솔 출처가 아니라 콘솔 API를 쿠키 달고 부르거나 콘솔 화면을 건드리지 못한다. 받기 이름은 `filename*=UTF-8''` 로 한글 그대로.
- `/api/refs/raw` 에 `?download=1` 을 더했다(상담 첨부 받기).

## 검증

- Flow 형검사 통과. 시험: `chatLinks` 7개, 서버 `/api/project-file` 4개(시안 HTML sandbox · 한글 받기 이름 · 절대 경로 302 · 밖 / `..` / `.env` / 없음 / 폴더 / 모르는 프로젝트 거절). 전체 449 통과 · 1 실패 — 앞서 적은 `access.test.ts`(변경과 무관).
- :4318 을 다시 빌드해 띄우고 실제 파일로: PNG 200 · 받기 이름 · 절대 경로 302 · `.env` 403. 오늘 대화방 화면에서 `workspace/records/log.md` 등 경로가 밑줄 + 「받기」로 나온다: [대화방](채팅-링크-열기받기_20261016_v1/room.png). 그 대화방에 적힌 시안 `폴더문서-화면4안_20261016_v1/index.html` 을 새 길로 열면 탭 · 스크립트까지 돈다: [시안 열기](채팅-링크-열기받기_20261016_v1/draft.png).
- 확인하지 못한 것: 상담 창은 화면으로 보지 않았다(같은 `ChatText` 를 쓰고 형검사만 통과). 원격 토큰 접속에서는 시안 HTML 이 부르는 옆 파일(css · 이미지)이 sandbox 출처라 쿠키가 안 실려 401 이 날 수 있다 — 로컬 접속은 영향 없음.
