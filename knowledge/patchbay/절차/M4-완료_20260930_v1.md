## 한 방향이다

생성은 1회성 스캐폴드다 (원칙 3). `--force`는 두지 않았다 — 있는 파일을 덮는 스위치가
생기면 왕복 동기화와 같은 일이 생성기 이름으로 돌아온다.

```
$ patchbay ir generate --project <alias>
  → <레포>/src/agent/{state.ts, graph.ts, evals.test.ts}

$ (같은 명령을 다시)
  → 이미 있는 파일은 그대로 두었다.
```

사람이 `graph.ts`에 적은 라벨이 두 번째 실행 뒤에도 남아 있는 것을 테스트가 확인한다.

## 통과 조건

| 조건 | 확인 |
| --- | --- |
| 고정 자료에서 생성물이 스냅샷과 같다 | `ir/__fixtures__/scaffold/` 세 파일 |
| 두 번째 실행은 기존 구현 파일을 덮지 않는다 | 라벨을 고친 뒤 재실행 → 고친 라벨이 남음 |
| 노드 집합 대조 | `addNode` id ↔ `ir.nodes[]`. 어긋나면 덮지 않고 말한다 |

실물 검증 프로젝트의 역추출 대조는 **구현이 끝난 뒤** 수락 시험으로 남긴다
(사용자 결정 2026-09-28). 구현 중에 그 레포를 입력으로 쓰지 않는다.

## 설계 판단

1. **생성은 순수 함수, 쓰기는 스튜디오.** `generate.ts`는 문자열만 돌린다. 덮어쓰기 금지는
   `writeScaffold` 한곳에 있다 — 생성기가 쓰기도 하면 「덮지 않는다」가 호출부마다 갈린다.
2. **1.9를 통과하지 못한 IR은 파일을 만들지 않는다.** 2단계는 1단계의 산출물만 먹는다.
3. **런타임 강제는 생성된 코드의 몫이다** (명세 §4.3). 노드 껍데기에는 권한 주석과,
   되돌릴 수 없는 툴이 있을 때만 `humanGate` 스텁을 넣는다. Patchbay가 invoke를 가로채지 않는다.
4. **모델 평가는 invoke하지 않는다.** CI가 실제 모델 API에 매달리지 않게, `kind: model`은
   고정 응답 어댑터 주석과 실패 throw만 남긴다.

2.4(노드 내부를 채워 테스트를 통과시키기)는 호스트 모델의 일이다. 이 마일스톤은 실패하는
틀을 만드는 데까지다.
