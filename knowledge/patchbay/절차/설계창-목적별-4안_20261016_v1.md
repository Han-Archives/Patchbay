# 설계 창 목적별 4안 · 2026-10-16

사용자 요청: 왼쪽 바 「설계」를 세 목적(새로 설계 · 설계안 확인 · 설계 수정)에 맞춰 개편한다. 저장 방식 ① 대표 설계안 하나(판만 올림)를 2안, ② 설계안 여러 개를 2안으로 그려 검토한다.

상태: 승인 대기. 독립 HTML 시안이며 제품 코드는 바꾸지 않았다. 예시 프로젝트 「동네 책 나눔」의 예시 데이터만 쓴다.

시안: [화면 열기](설계창-목적별-4안_20261016_v1/index.html). 위 탭으로 안을 바꾼다. 1-A는 목적 카드, 1-B는 왼쪽 단계, 2-A는 카드 두 장, 2-B는 그래프 노드를 눌러 본다.

## 네 안 공통

- 범위는 「할 수 있는 일 · 할 수 없는 일 · 보류」 세 칸으로 나눈다. 줄마다 근거 표시를 붙인다. 근거는 코드에서 확인한 사실, 사람이 확인해야 하는 것, 판단할 수 없는 것 세 가지다.
- 수정은 채택본을 복사해 초안으로 연다. 비교 보기는 추가를 보라, 변경을 주황, 삭제를 빨강으로 표시한다. 채택 조건(11절 확인 · 검사 통과)은 지금과 같다.
- 영향 그림은 바뀐 절에서 할일 · 흐름도 항목으로 이어진다. 승인한 줄만 새 작업이 된다.

## ①을 고르면 먼저 할 것

- 상담 초안은 `ir.proposed.yaml`이 없으면 빈 초안에서 시작한다(`draftWrite.ts:181-191`). 채택본을 복사해 시작하는 경로를 더한다. 시험 항목 추가(`irStore.ts:140-152`)가 이미 같은 방식을 쓰고 있다.
  - 확인함: 채택해도 초안은 지워지지 않는다(`irStore.ts:186-187`). 그래서 상담으로 만들어 채택한 프로젝트는 이미 채택본과 같은 초안 위에서 수정이 이어진다. 빈 초안 문제는 **초안 파일이 아예 없는 경우**에만 생긴다.
  - 확인함: 판 번호는 채택할 때 「채택본 판 + 1」로 정해지고, 초안에 적힌 `version`은 무시된다(`irStore.ts:219,260`). `draftWrite.ts:190`의 1은 화면에도 쓰이지 않아 문제가 아니다.
  - 확인함: 절 확인은 절 내용의 digest로 묶인다(`review.ts:53-54`). 수정하면 바뀐 절만 「확인 대기」로 돌아가고 나머지는 확인 상태로 남는다. 「바뀐 부분만 다시 검토」는 지금 구조로 된다.
- 설계 절과 할일 · 흐름도 항목을 잇는 연결 정보는 지금 없다. 영향 그림을 그리려면 이 정보를 새로 만들어야 한다.
