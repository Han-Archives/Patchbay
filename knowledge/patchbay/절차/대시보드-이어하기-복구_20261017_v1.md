# 대시보드 이어하기 복구

사용자: 대시보드 맨 위 이어하기가 이전 작업 화면으로 이동하지 않는 문제를 확인하고, 수정 전에 Claude로 검증받기.

## 원인과 수정 전 검증

기존 `DashboardPane.continueRoom`은 최신 대화방 hash만 바꿨다. App의 hash handler도 대화 열림만 설정하고 중앙 `place`나 접힘을 바꾸지 않았다. 지난 작업 화면을 저장하는 코드도 없었다.

격리 Chrome에서 RAG→대시보드→대화 접힘→이어하기를 재현했다. main은 dashboard, 접힘 true인 채 hash만 바뀌었다. 실제 모델 호출은 0회였다.

제품 수정 전 Claude Opus 5.5에 코드·재현·수정안을 검증받았다. 원인 분석은 맞고 C1~C6 보완 후 진행 가능이라는 **조건부 가능** 판정이었다. 검토 전후 App/DashboardPane의 파일 해시가 동일함을 메타에 기록했고, 검토가 끝난 다음 수정했다. 실제 코드 열람·실행을 Claude가 한 것으로 표현하지 않는다.

검토 입력·원문·실행 메타·수정 전 캡처·반영표는 `workspace/records/patchbay/절차/대시보드-이어하기-복구_20261017_v1/`에 보존했다.

## 적용

- `workspaceNavigation.ts`: 프로젝트별 작업 화면 allowlist와 버전 있는 브라우저 저장 값, 손상·저장소 실패 처리, 화면/대화/시작의 단일 resolver.
- App 공통 `navigate`: 사용자 클릭에서만 작업 화면 기록. dashboard/home·초기 조회·SSE·프로젝트 전환·이어하기는 기록을 덮지 않음.
- Dashboard 버튼: 저장 화면을 우선 복원하고 label/title/aria-label과 실제 동작을 같은 resolver에서 선택.
- 작업 기록이 없으면 기존 RoomPanel 선택을 유지한 채 대화를 펼치고 입력에 초점. 방이 없으면 기존 시작하기 유지. Dashboard가 방을 따로 고르거나 hash를 만들지 않음.
- 기존 room deep link는 alias 목록 로드 이후 확인하며 잘못된 인코딩·미등록 alias를 무시. 실제 hashchange 때 접힘 해제. 목록 재조회만으로 같은 hash를 재적용하지 않음.
- Log 날짜는 해당 프로젝트의 복원 문맥으로 저장. 저장소가 차단돼도 현재 세션에서는 복원.

저장 값은 `patchbay.last-work.<alias>`의 `{version:1,alias,place,logDate?}`다. 문서 본문·대화 내용·입력 초안은 저장하지 않는다. 복원 범위는 상위 작업 화면과 명시적으로 연 Log 날짜다. 새로고침 직후는 대시보드이며 버튼으로 복귀한다.

## 확인

관련 시험 53개 통과(화면 계약 5·대시보드 6·서버 42). 초기 네이티브 파일 감시 시험은 EMFILE로 실패해 폴링으로 재실행한 결과다. 제품 코드를 바꿔 시험 오류를 숨기지 않았다. Flow 형검사·빌드 통과.

브라우저 검증은 [validation.json](대시보드-이어하기-복구_20261017_v1/validation.json)에 있다. RAG·설계·아키텍처·파일·그래프·Log 날짜 복원, A/B 분리, 새로고침, SSE, 대화 접힘·선택·새 대화·시작하기, 초기 deep link, 잘못된 hash, 저장소 차단과 모바일을 확인했다. 모델 호출 0회.

제품 코드는 App/DashboardPane/브라우저 navigation 계약만 변경했다. 서버 API와 모델 실행 동작, 할일·기획 단계 완료는 변경하지 않았다.


최종 적용: 기존 4318에서 RAG→대시보드→이어하기가 실제 docs 화면으로 복귀하는 것을 확인했다. 아키텍처 원본 배치 시험 8개도 통과했고 배치도·진행 기록을 갱신했다. 이번 수정 전에는 최근 화면 정보가 없었으므로 이후 방문한 화면부터 기억한다.
