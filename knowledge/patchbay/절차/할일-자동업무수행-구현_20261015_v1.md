# 할일 자동 업무 수행 — 구현

작성일: 2026-10-15. 사용자 요청: 요구사항과 시안을 바탕으로 실제 기능 구현.

## 제공한 동작

- 할일 ‘미리 준비’에서 주 담당 Claude/Codex와 최대 5개를 선택한다. 선택 순서가 아니라 저장된 할일 목록 순서로 처리한다.
- 담당 LLM이 업무 유형과 모드를 판단한 뒤, 해당 모드 규약에 따라 계획·완료 조건·연계 추천·산출물 본문·승인 후 남은 작업을 만든다. 준비 호출은 모두 읽기 전용이다.
- 문서·HTML 시안·텍스트·unified diff를 별도 준비본으로 보존한다. HTML은 외부 리소스와 스크립트를 차단한 iframe에서 미리 보고, 모든 산출물을 내려받을 수 있다.
- 할일의 연결 대화를 재사용하고, 유형 판단·선택 이유·계획·연계·준비 결과·사용자 승인·검증 결과를 기록한다. 방과 대화 목록에 보라색 및 ‘미리 준비’ 표시가 붙는다.
- ‘준비 결과’와 ‘대화 기록’을 분리해 긴 대화가 준비 결과를 화면 밖으로 밀어내지 않게 했다. 검토 대화의 일반 보내기는 읽기 전용으로 제한해 승인 우회를 막는다.
- 선행 관계는 참고/필수로 나눈다. 필수 선행이 미완료면 산출물이 있어도 대기하며, 다시 준비로 확정 결과를 반영한다. 미래 할일과 중복된 연계는 거절한다.
- 그대로 진행 → 해당 준비본 실행 확인 → 원본 해시·요구사항·선행 버전·할일 순서 확인 → 승인한 산출물로 반영 → 완료 조건별 검증 근거 확인 → 할일 완료와 기존 기록 보관으로 이어진다.
- 수정 요청은 새 준비본을 만들고 이전 본문을 보존한다. 보류·다시 준비·묶음 중지를 제공한다. 한 항목이 실패하면 남은 묶음은 중지한다.
- 서버 재시작 뒤 준비 중 항목은 중지, 반영 중 항목은 확인 필요로 복원한다. 자동으로 재반영하지 않는다.

## 구현 경로

- 커널: `app/packages/core/src/studio/todoPreparationStore.ts`. 직렬화·원자 저장, 준비본 이력·연계·산출물·상태 보존. 모델 호출 없음.
- 호스트: `app/apps/flow/src/todoPreparation.ts`. 기존 `defaultRoomRunner`와 프로젝트 실행 잠금을 재사용한 순차 호출·승인 제어.
- 화면: `TodoPreparationPanel.tsx`, `TodoPane.tsx`, `RoomPanel.tsx`, `console.css`.
- API: `GET /api/todo-preparations`, `POST /api/todo-preparations/start`, `POST /api/todo-preparations/action`. 기존 인증·조회/쓰기 분리와 출처 검사를 따른다. 목록 조회에서는 산출물 본문을 생략해 반복 전송을 줄인다.
- 원문: `projects/<alias>/todo-preparations.json`. 커널 저장 함수로만 쓴다. 저장구조·접근 등급·아키텍처 맵·개요를 함께 갱신했다.

## 검증

Core 빌드, Flow 형검사·클라이언트 및 서버 빌드 통과. 신규 준비 기능 11개, 기존 할일 5개·대화 호출 16개·테스트 실행 10개·대화 저장 7개·할일 저장 4개, 서버 37개: 서로 다른 시험 총 90개 통과.

서버 시험의 SSE 항목은 샌드박스 EMFILE로 최초 실패했으며, 제한 밖에서 37개 전체가 통과했다.

실제 빌드와 임시 작업 공간에서 Chrome으로 최대 5개 선택, 여섯 번째 선택 제한, 순차 준비, 산출물 미리보기, 대화 색상, 특정 준비본 승인, 임시 프로젝트 파일 반영, 완료 보관, 새로고침 복원, 모바일 가로 넘침 및 런타임 오류를 검증했다. 브라우저 검증의 모델 응답은 테스트 대역이며 실제 유료 LLM 호출은 수행하지 않았다.

## 동작 경계

초기 버전은 수동 시작·개별 승인이다. 필수 입력이 없는 업무는 계획과 대기 사유를 제공하며, 완료될 때 자동으로 다시 생성하지 않는다. 담당을 선택해 다시 준비할 수 있다. 주 담당은 권한 제한이 가능한 Claude/Codex로 한정한다.

원본 비교는 git 추적/미추적 파일(일반 폴더는 생성물 제외 파일)의 내용 해시를 사용하므로 관련 없는 원문 변경도 재검토를 요구할 수 있다. 읽기 전용 준비 단계에서는 테스트 명령을 실행하지 않는다. 최종 검증은 담당 LLM이 실제 수행한 완료 조건별 근거를 보고하는 방식이며, 별도 독립 검증자가 자동 판정하는 기능은 추가하지 않았다. 외부 게시·배포·삭제·서버 재시작은 승인된 산출물 실행에도 포함하지 않는다.

## 로컬 반영

기존 4318 서버에서 진행 중 LLM 작업이 없는 것을 확인하고 접속 설정을 메모리에서 보존해 재시작했다. `GET /api/todo-preparations?alias=patchbay`의 정상 응답을 확인했다. 실제 사용자 할일은 임의로 준비하거나 실행하지 않았다.

새 프런트엔드 자산과 준비 API를 실제 4318에서 확인하고 아키텍처 배치도를 갱신했다. 임시 4330 검증 서버는 종료했다.
