# 태그와 Workflow 색상 확장

작성일: 2026-10-30 (Asia/Seoul)

사용자 요청: 태그와 Workflow에 보라색이 너무 많이 보여 단순하므로 색상을 늘려 달라는 요청.

회색 작업 바탕은 유지하고, 태그의 종류와 Workflow의 단계를 서로 다른 색으로 구분했다. 이전의 「상태에만 색을 사용」하던 표현 범위를 이번 사용자 요청에 따라 종류·단계 구분까지 넓혔다.

## 화면 표현

| Workflow 단계 | 색 |
| --- | --- |
| 설계 | 파랑 `#2D63A8` |
| 구현 | 청록 `#19776D` |
| 테스트 | 주황 `#98611C` |
| Review | 보라 `#7851A9` |
| 결과 | 초록 `#327448` |

각 단계의 제목·윗 테두리·진행 막대에 같은 색을 사용한다. 현재 단계의 배경은 해당 색을 옅게 섞고, 선택 외곽선과 현재 단계로 향하는 화살표도 같은 색으로 맞춘다. 완료는 초록 점과 초록 완료 칩으로, 대기는 점선으로 구별한다. 단계의 고유 색과 상태를 함께 읽을 수 있도록 상태 글자·기호·점선·진행 수치는 유지했다.

태그는 History·Workflow·Log가 기존 `tagColor()`를 공유한다. UI는 파랑, 데이터는 청록, 서버는 코랄, 문서는 금색, Agent·LLM은 보라, 대화창은 푸른 청록, 할일은 자주, 프로젝트는 회청색으로 표시한다. 지정하지 않은 태그는 기존처럼 이름으로 정한 색을 안정적으로 재사용한다. 작은 태그는 진한 글자와 해당 색을 옅게 섞은 배경을 사용한다.

대시보드 활동 달력과 Log 활동 격자는 청록 농도로 표현해 큰 보라색 면적을 줄였다. 날짜별 활동량을 나타내는 농도의 의미는 같다.

## 구현과 확인

- `ProjectCycleFlow.tsx`: 노드·연결·세부 단계에 단계 식별 클래스를 붙인다. 단계 전환과 진행 판정은 그대로다.
- `DashboardHistory.tsx`·`CycleTaskTable.tsx`: 공용 태그 색을 사용한다. 태그 이름·내용과 저장 형식은 바꾸지 않는다.
- `console.css`: 회색 표면 위에 단계·종류별 색과 별도의 초록 완료 표시를 적용한다.
- Flow 형검사·클라이언트/서버 빌드 통과. 고리·작업 상태·History 관련 시험 11개 통과.
- 브라우저에서 Workflow 다섯 단계의 서로 다른 색과 전환, History와 Workflow의 같은 태그 색 일치, 390px 모바일의 가로 넘침과 실행 오류를 확인했다.
- 관측한 태그의 글자/배경 대비는 최소 4.69:1이었다. 전체 제품 접근성 감사 결과는 아니다.
- 실제 화면과 검증 JSON은 `workspace/records/patchbay/절차/태그-Workflow-색상확장_20261030_v1/`에 보관한다. 브라우저 확인 중 실제 저장·실행 요청은 차단했다.
