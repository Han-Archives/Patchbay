## 1. 다른 웹페이지가 콘솔에 쓰기를 보낼 수 있었다

**재현:** 다른 출처에서 `content-type: text/plain` 으로 `POST /api/project/scan` → 200. 브라우저는 이 형식을
사전 확인 없이 보내고 응답만 숨긴다 — 콘솔이 떠 있는 동안 아무 페이지나 열면 채택 · 뼈대 생성 · 폴더 등록이
일어날 수 있었다. 콘솔에는 로그인이 없다.

**고침:** `writeGuard.ts` `foreignWriteReason` 을 `/api/*` 미들웨어로 모든 라우트 앞에 둔다.
쓰기(GET · HEAD · OPTIONS 밖)는 ① `application/json` 만 받고 ② `Origin` 이 있으면 요청 호스트와 같아야 한다.
①만으로도 다른 출처는 사전 확인에서 멈추고(CORS 허용을 내주지 않는다), ②가 한 겹 더다. 화면의 쓰기 호출은
전부 이미 JSON이라 바뀐 것이 없고, curl · CLI 처럼 `Origin` 없는 호출도 그대로 된다.

| 걸음 | 답 |
| --- | --- |
| 같은 출처 · JSON (화면과 같은 요청) | 200 |
| 다른 출처 · `text/plain` → `ir/adopt` | 403 · 「쓰기 요청은 content-type: application/json 이어야 한다」 |
| 다른 출처 · JSON → `build/generate` | 403 · 「다른 출처의 쓰기 요청은 받지 않는다」 |

## 2. 실패에서 만든 평가가 조용히 빠지는데 화면은 들어갔다고 했다

**재현:** 사람이 초안에 E7을 먼저 써 두고 「평가 초안 넣기」 → `added: ["E8"]`, 실패의 E7은 버려졌다. 그런데
`inDraft` 가 id 로만 보아 `E7 · E8` 이라 버튼이 「1 설계에서 검토」로 바뀌었다.

**원인 둘:** Core가 새 id 를 승인본만 보고 매겼고, 「이미 넣었나」를 id 로 판정했다.

**고침:** `draftEvalsFromRuns(ir, records, { draft })` — 초안을 주면 새 id 는 승인본과 초안 **둘 다** 피해서
매기고, 같은지는 id 가 아니라 **(노드, 실패 종류)** 로 본다(`input` 이 Core가 쓴 모양
「고정 응답 어댑터: <종류> (<runId> 재현)」인 행). 이미 있는 실패는 `inDraft: true` 이고 `draftsAsIrEvals` 가
다시 내보내지 않는다. 사람이 `input` 을 고쳐 썼으면 다른 행으로 본다 — 조용히 빠지는 것보다 겹쳐 보이는 쪽을
사람이 고칠 수 있다. 초안 읽기는 Core `readProposedIrIfValid` 하나로 CLI · 콘솔 보기 · 콘솔 쓰기 · MCP
`get_runs` 가 같이 쓴다.

| 걸음 | 답 |
| --- | --- |
| 초안에 사람의 E7 → `GET /api/runs` | `ids E8 E9` · `inDraft []` |
| 넣기 | `added E8 E9` · 사람의 E7 그대로 |
| 또 넣기 | 409 · 「같은 실패의 평가가 이미 초안에 있다 — E8 · E9」 |
| CLI `runs draft-evals --write` | 「(이미 초안에 있다)」 · 새로 넣을 것 없음 |

## 3. 화면에 용어집이 금지한 이름이 나갔다

`terms.mdc`: 잭 → **항목**, inferred → **스캔 결과**. 고친 곳: 스캔 결과 줄(`scanNote`), 미스캔 안내(`App.tsx`),
지식 탭 미스캔 안내, 그리고 원래 있던 구조 칩 「이름 없는 잭」 → **「분류 안 된 항목」**. 이 날의 기록 문서도 맞췄다.
구조 머리의 「Atlas」 제목은 그대로 남아 있다 — 용어집은 「구조 요약」이다(이번 범위 밖).

## 4. 항목 설명을 너무 자주 다시 읽었다

재스캔 때 `StructurePane` 의 설명 읽기 조건을 `[view.alias]` → `[view]` 로 바꿨는데, `view` 는 진행 기록이
바뀌어도 새로 온다. 그때마다 설명이 비었다가 모든 항목 파일을 다시 읽었다.

**고침:** 조건을 `structureKey(view)`(별칭 + 구조 칸)와 스캔 버튼을 누른 횟수로. 같은 항목의 파일 내용만 바뀐
재스캔도 잡는다. 다시 읽는 동안은 옛 설명을 두고, 프로젝트가 바뀔 때만 비운다.
