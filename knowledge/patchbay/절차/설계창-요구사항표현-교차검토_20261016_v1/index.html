요구사항 표현 — 교차 검토 최종 3안

Claude 4안 + Codex 4안 · 예시 데이터(동네 책 나눔) · 제품 코드 아님

무엇을 보여 줘야 하나 (모든 안 공통)

추적 관계 목적 → 요구사항 → 예외·검증 → 흐름도 → 시험, 요구사항마다 6칸(왜 · 무엇 · 경계 · 확인 · 연결 · 미결)이 얼마나 채워졌는지, 판이 바뀌면 어느 칸이 바뀌었는지. 각 안은 이 셋 중 무엇을 그림의 주인공으로 삼느냐가 다르다.

교차 검토 — 「정보가 보고 바로 전달되는가」

교환 · 교차 검토 결론

Claude → 관계·구체화A는 전체 추적이 빠르지만 커지면 선이 엉킨다. B는 한 요구사항을 명확하게 읽지만 전체 관계가 약하다. C는 목적 근거, D는 대량 목록에 강하다.
Codex → 변화·행동 흐름E는 변경의 파급을, G는 사용자의 실제 행동과 예외를 즉시 보여 준다. F는 한 줄 집중에 좋지만 B와 겹치고, H는 확장성은 좋지만 새 표현법은 아니다.
선정 1 · 추적+해부A와 B를 결합. 전체 고리를 본 뒤 선택한 요구사항의 빈칸과 문장 조각을 읽는다.
선정 2·3 · 변화 전파 / 시나리오수정 검토는 E, 신규 요구 구체화는 G가 가장 직접적이다. 하나의 만능 화면보다 작업 목적에 따라 바꾼다.

최종안은 인기 투표가 아니라 서로 다른 질문을 가장 빨리 답하는 조합이다: ① 어디에 연결됐나 ② 무엇이 바뀌나 ③ 사용자는 어떤 순서와 예외를 겪나.
