# 대화방 — 방이 맥락의 경계 · 2026-10-09

| 항목 | 값 |
| --- | --- |
| 요구 | 대화방을 여러 개로 두어, 한 기록이 길어져 다음 호출의 맥락이 커지는 것을 막는다 |
| 상태 | 설계. 콘솔의 방 여닫기는 아직 고치지 않았다 |
| 이미 있는 것 | 방 파일은 이미 여러 개다 (`rooms/<id>.jsonl`). 호출은 그 방의 말만 넣는다 (`roomPrompt`). 상담은 끝내면 보관하고 새 세션은 초안만 읽는다 |

## 한 줄

다음 모델이 읽는 것은 지금 말하는 방 하나다. 남겨 둔 방은 목록에서 읽고, 호출에는 넣지 않는다. 새 방은 비어 있다.

```
남겨 둔 방 ──읽기──▶ 사람
                      │
지금 방 ─────────────▶ 다음 호출 (이 파일만)
                      │
새 방 ──비어 있음────▶ 다음 말부터
```

## 화면

방 목록이 대화 옆에 있다.

| 상태 | 입력 | 다음 호출 |
| --- | --- | --- |
| 지금 방 | 연다 | 이 방의 말만 |
| 남겨 둠 | 닫는다. 기록은 보인다 | 넣지 않는다 |
| 새 방 | 빈 칸 | 아직 말이 없다 |

남겨 둔 방에서 「이 방에서 계속」을 누르면, 그때부터 그 방 전체가 다시 호출에 들어간다. 기본은 읽기다.

방 머리에는 말 수와 글자 수를 보여 준다. 파일에 있는 줄로 센다. 토큰 수로 자동으로 자르거나 방을 닫지 않는다. 닫는 시점은 사람이 정한다. 상담 끝내기와 같다.

## 이전 방을 잇는 법

방 전체를 새 방에 붙이지 않는다. 붙일 수 있는 것은 직전 방의 짧은 요약 하나다. 이미 있는 `roomMemory`다. 사람이 물은 말 최근 6줄, 나온 말 최근 4줄, 한 줄 160자. 모델을 부르지 않는다.

요약은 새 방에 하나다. 방마다 요약을 이어 붙이면 다시 길어진다.

## 하지 않음

- 커널이 모델을 불러 방을 요약하기
- 말 수가 차면 방을 자동으로 닫기
- 상담 보관(`consult/archive/`)과 방 파일을 한 폴더로 합치기
- 그래프 멈춤 기록(`threads/`)을 이 경계에 넣기
