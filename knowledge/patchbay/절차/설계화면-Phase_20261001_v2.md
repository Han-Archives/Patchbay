```
Phase ─ 1단계 안의 아홉 칸. 위에서 아래로 채우고, 누르면 그 칸의 창이 옆에 열린다.
```

아무 Phase도 고르지 않았을 때 오른쪽 열에는 「Phase를 누르면 그 칸의 창이 여기 열린다.」가 점선 상자로 있다.

## 설계 판단

1. **창은 스크롤을 따라온다 (`position: sticky`).** 옆에 두면 아래쪽 Phase(9, 최종 검사)를 눌렀을 때
   창이 프로세스 맨 위 높이에 그려져 화면 밖에 있게 된다. 위에 붙여 두고 창이 길면 창 안에서 스크롤한다.
   창은 프로세스 끝 아래로는 내려가지 않는다 — 창이 화면보다 높으면 위가 밀려 올라간다.

2. **폭은 화면이 아니라 설계 영역으로 잰다 (container query).** 콘솔은 왼쪽 사이드바가 있어 창 폭과 설계
   영역 폭이 다르다. 설계 영역이 **560px 이하**면 예전처럼 창이 프로세스 아래로 내려간다 — 그보다 좁으면
   둘을 나란히 놓았을 때 어느 쪽도 읽을 수 없다. 처음엔 680px로 잡았는데 테스트 브라우저의 설계 영역이
   633px라 옆으로 안 붙었다.

3. **프로세스 열은 설계 영역의 38% (220~320px).** 처음엔 최대 300px까지 썼더니 창이 319px만 남아 표가
   세로로 길어졌다. 38%로 줄이니 같은 폭에서 프로세스 240px · 창 378px.

4. **Phase 한 줄을 두 줄로 고정했다.** 좁은 열에서 `Phase 3 권한 경계 1.2 통과` 를 한 줄로 흘리니 칸마다
   다른 자리에서 꺾였다. 이제 첫 줄이 `Phase 3 · 1.2 …… 통과`, 둘째 줄이 칸 이름이다 — 상태가 늘 같은
   자리(오른쪽 위)에 있어 위아래로 훑을 때 읽힌다.

5. **창 머리줄은 한 줄로 둔다.** 「닫기」를 × 버튼(마우스를 올리면 「닫기」)으로 바꾸고, 칸 이름이 길면
   말줄임으로 줄인다. 칸 이름은 왼쪽 프로세스에도 있으니 잘려도 잃는 것이 없다. 편집기의 머리줄도 같다
   (「이 칸 저장」 다음에 ×).

## 실측

```
설계 영역 633px   프로세스 240px · 창 378px · 나란히 (창 왼쪽 ≥ 프로세스 오른쪽)
Phase 3 열기      권한 표 · 「이 Phase 고치기」 → 편집기, 머리줄 39px (한 줄)
Phase 9 열기      프로세스를 아래로 내린 상태에서 창이 설계 영역 위에 붙어 보임 · 머리줄 39px
설계 영역 520px   창이 프로세스 아래로 (sticky 해제)
```
