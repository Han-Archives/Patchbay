# 요구사항 30개 · 개요+초점 시각 검토

2026-10-16 · 상태: 검토용 HTML 작성 완료, 제품 적용 전.

사용자 요청: 최근 교차검토 HTML의 개요+초점 안이 요구사항 20~30개에서 어떻게 동작하는지 직접 시각적으로 검토할 수 있는 HTML 문서를 만든다.

[HTML 시안 열기](요구사항-30개-개요초점_20261016_v1/index.html)

## 검토 순서

1. 전체 30개를 5개 기능 묶음으로 훑는다. 검색과 기능 필터를 사용하고, 목록의 6칸 상태를 확인한다.
2. 상단 「직접 변경 3」을 눌러 이번 상담에서 바뀐 요구사항만 본다.
3. R14를 골라 「변경 전후」의 24시간 → 12시간, 무응답 자동 취소, 검증 예시와 시험 연결을 확인한다.
4. 「흐름·시험」에서 현재와 변경 후의 노드·분기를 비교한다. R26·R28은 직접 수정되지 않고 영향 확인 대상으로 남는다.
5. R23은 미결 질문이 있어 확정 버튼이 비활성이다. 예시 답변을 적용하면 해제 조건·검증·시험 계획과 대화 근거가 갱신되고 확정할 수 있다.
6. 「확정 가능한 변경 선택」과 하단 선택 확정으로 여러 항목을 함께 검토한다. 개별 보류와 되돌리기도 가능하다.
7. 「검토 결과 모아보기」에서 확정·보류·남은 검토를 비교한다. 현재 설계 v2로 전환하면 기존 내용을 확인할 수 있다.

## 표현 원칙

- 대화 원문 → 변경 이유 → 요구사항 → 관련 흐름 → 시험을 요구사항 ID로 연결한다.
- 직접 변경 3건과 영향 확인 3건을 구분한다. 연결되어 있다는 이유만으로 다른 요구사항을 자동 수정하지 않는다.
- 요구사항 전체를 매번 승인하지 않고, 이번에 바뀐 항목만 선택해 결정한다.
- 설계 확정·구현 진행·시험 결과를 별도로 표시한다.
- 동네 책 나눔 서비스는 가상의 예시다. 대화도 고정 예시이며 실제 LLM 호출은 없다.
- 실제 제품의 설계 판·대화·할일은 변경하지 않는다. 브라우저 저장이 가능한 곳은 검토 결과를 해당 브라우저에 저장하고, Patchbay 파일 미리보기에서는 화면을 닫기 전까지만 유지한다.
- 외부 라이브러리·서버 없이 HTML 파일 하나로 실행한다.

## 검증

Chrome에서 47개 확인 항목을 통과했고 JavaScript 실행 오류는 없었다.

- 요구사항 30개·기능 5묶음·6칸 표시
- 변경·영향·미결·확정 필터, ID·본문 검색, 빈 검색 결과, 기능별 필터
- 변경 전후 비교, As-is/To-be 흐름도, 시험 계획과 실제 결과 구분
- 미결 질문에 따른 확정 제한, 예시 답변 적용과 대화 근거 갱신
- 개별·일괄 확정, 보류, 되돌리기, 새로고침 후 브라우저 저장 복원
- 검토 결과 창, 키보드 Escape 닫기
- 1512·1280·1024·768·390px 화면에서 가로 넘침 없음
- Patchbay의 실제 파일 미리보기에서 표시·확정과 저장 제한에 따른 대체 동작
