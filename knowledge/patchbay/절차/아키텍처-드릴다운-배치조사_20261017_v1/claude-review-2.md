# Claude 2차 검토 원문

2026-10-17. `claude-opus-5-5`. 도구·웹·파일 수정 없이, 1차 지적을 반영한 개정 문서와 HTML만 보고 쓴 답이다. 중심은 그 수정이 화면의 거짓을 없앴는가이다.

**한 줄 판정**: 시나리오, 요소 id, 경계 노드, 저장 검사는 닫혔다. 대신 분해 장과 순서 번호가 새 거짓을 만든다. 문서의 JSON 예시는 시안과도, 문서 자신의 시나리오 규칙과도 어긋난다.

## 1차 높음

1. **남음.** 시나리오(r7·r8·r9, via 있음)는 맞다. 분해 `kernel-parts`는 문제가 있다. 부모 선 r2~r6을 커널 노드에 그대로 두고 자식 선 r7·r9를 더한다. 그래서 커널이 자기 분해 안에 자식의 형제로 서고, 「작업」과 「기록」이 두 번 보인다. 문서 JSON의 `kernel-write`도 r2·r3과 r9를 함께 넣어 시나리오 규칙을 어긴다.
2. **닫힘.** `elements`는 한 곳에 있고, 장은 `relationshipIds`의 부분집합이며, 경계 노드는 같은 id를 쓴다.
3. **닫힘.** 시스템 안 요소는 `boundary`로 그리고 바깥으로 그리지 않는다. 다만 새로 고칠 것 1번이 생긴다.
4. **닫힘.** `storeFacts`는 via 없는 관계로 모델 전체를 본다. 장에서는 「이 장에서 씀」을 따로 적는다.
5. **남음(실행 장).** 구조 장과 흐름 장은 노드와 옆에 미확인이 나온다. 실행 장 예시는 `evidence:"run"`이라 미확인이 빠지고, 「실행됨 · 지금」이 실제 실행처럼 보인다.
6. **남음.** 시나리오의 1·2·3은 맞다. 그러나 `step`이 관계에 붙어 있어 구조 장에 1~6이 순서처럼 나온다. 분해 장에는 1, 2, 2, 3, 3, 4, 5, 6이 섞인다.

## 새로 고칠 것

1. **경계가 역할을 지운다.** `role:"boundary"`가 store를 덮는다. 시나리오의 작업 공간이 저장 색 대신 점선 「경계」로 나오고, 저장 필터로도 꺼지지 않는다. 「어디에 저장되나」를 묻는 장에서 저장이 사라진다. `role`은 원래 값을 두고 `boundary:true`와 `ref`를 따로 둔다. 필터는 원래 role에 건다.
2. **분해의 형태가 정의되지 않았다.** 초점 요소는 노드로 그리지 않는다. 부모 관계마다 그것을 잇는 자식 선이 via로 정확히 하나 있어야 한다. 지금 r4·r5·r6에는 대응하는 자식 선이 없다. 검사 규칙을 문서에 적는다. via 대상 관계의 한 끝은 focus, 다른 끝은 경계 요소와 같고, 방향과 effect도 같아야 한다.
3. **step을 장에 둔다.** `views[].steps: {relId: n}` 형태로 scenario에만 둔다. 같은 관계를 두 시나리오가 쓰면 관계에 붙은 번호는 충돌한다. 구조 장과 분해 장에는 번호를 쓰지 않는다.
4. **빵 부스러기가 방문 기록이다.** 분해 장에서 커널의 「안으로」로 시나리오를 고르면 「구조 / 커널 분해 / 커널의 한 번 기록」이 된다. 형제 장이 자식처럼 보인다. 부스러기는 focus의 parent 사슬로 만들고, 방문 이력은 「뒤로」로 분리한다.
5. **선택 밝힘이 틀린다.** 선을 흐리게 할지를 `!touch.has(e.from)`로만 정한다. 작업 공간을 고르면 커널→LangGraph 선도 밝다. `e.from===selected || e.to===selected`일 때만 밝힌다.
6. **문서 JSON 예시를 시안과 맞춘다.** r2가 정의되지 않았고, r9의 출발이 시안은 `commit`, 문서는 `check`다. 다음 모델은 마크다운을 먼저 읽으므로 이 예시가 그대로 계약이 된다.
7. **저장 미완 표시가 없다.** 모델 전체에서 읽기나 쓰기가 없을 때 「미완」을 띄우는 자리가 시안에 없다. 지금은 「없음」만 나와 완성과 구별되지 않는다.

## 시안이 문서와 다른 점

- 실행 장 노드에 실행 상태가 겹쳐 보이지 않는다. 옆 패널에만 있다.
- 「위로」와 「뒤로」 버튼이 없다. 경계 노드는 「위 장」이 아니라 항상 구조 장으로 간다. 세 단까지 열면 틀린다.
- 양방향 선(r2/r6, r3/r4)이 같은 경로와 같은 라벨 자리에 겹친다. 라벨 둘이 포개져 한 방향 선으로 읽힌다. elkjs로 옮길 때 평행 선 분리와 선 라벨 배치를 옵션으로 명시해야 한다.
- 옆 패널의 미확인 문장은 근거와 상관없이 고정 문자열이다. 근거가 붙어도 미확인으로 나온다.
- 「바깥」 필터가 있지만 예시에 바깥 요소가 없어 동작을 확인할 수 없다.
