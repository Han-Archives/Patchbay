# Claude 4차 검토 원문

2026-10-17. `claude-opus-5-5`, Claude Code 세션. 1~3차와 달리 저장소 코드(`layout.ts`, `irCanvas.ts`, `ArchitecturePane.tsx`)와 대조했고, 수정 뒤 시안을 헤드리스 Chromium으로 눌러 확인했다. 중심은 3차 반영 뒤에도 남은 거짓과, 구현으로 넘어갈 때 빠진 것이다.

**한 줄 판정:** 3차 항목(분해 검사가 장 안만 세기, 실행 장의 「위로」, 흐린 선 글자, 출입 노드, 범위 문장, 라벨, JSON 예시 표시, 목적지 문장)은 닫혔다. 대신 분해의 자리, 모델의 경계, 선의 근거, 지금 콘솔의 배치가 다음 모델이 그대로 가져갈 계약을 흔든다.

## 높음

1. **분해가 「흐름」 장 아래에 있었다.** 문서는 "구조는 무엇이 있는지, 흐름은 한 일이 실행되는 모습"이라고 정의한다. 분해는 arc42 빌딩 블록 2단(흰 상자)이라 구조다. 시안에서 분해를 열면 빵 부스러기는 「구조 / 커널 / 커널 분해」인데 상단은 「흐름」이 눌려 있었다. 결론 표의 흐름 행은 시나리오만 말해 「칸 전환」과도 어긋났다.
2. **미확인 자리로 가는 선 r11~r14가 모델 `relationships`에 있었다.** 끝 `gap-*`는 한 장의 `slots`에만 있는 id다. "요소와 관계는 모델에 한 번"과 충돌하고, from/to가 요소인지 검사하는 구현은 깨진다. 같은 요소의 분해 장이 둘이면 자리 id가 겹친다.
3. **관계에 근거 칸이 없었다(3차 #3 반만 닫힘).** 「어디에 저장되나」라는 주장은 선이 한다. r7·r9는 부분에 닿고 r11~r14는 자리로 가는데, 둘 다 근거가 없어 기준이 "예시가 그렇게 정했다"뿐이었다.
4. **지금 콘솔의 배치를 다루지 않았다.** `layout.ts`는 dagre/elk 없는 직접 짠 층 배치이고 순환에 든 노드를 모두 0열에 둔다(`layout.ts:66`). 구조 장의 콘솔↔커널, 커널↔작업 공간 순환은 이 배치로 무너진다. 이것이 elkjs의 실제 근거인데 빠져 있었다. 또 React Flow는 선을 자기 곡선으로 그리므로 "직교 라우팅을 켠다"만으로는 화면이 바뀌지 않는다. elk의 선 경로(`sections`)를 그리는 사용자 정의 선과 라벨 크기 입력이 필요하다.

## 중간

5. 실행 장 목적지가 데이터에 없었다. `run` 장이 JSON에 없고 시안은 `id === "langgraph"`로 박아 두었다.
6. `boundary`·`ref`가 저장값인지 계산값인지 문서가 말하지 않았다(시안은 계산).
7. 검사의 빈 곳. 시나리오 장에는 검사가 없었고, 분해 장도 `via` 없는 선이 경계 요소에 닿는 경우를 잡지 못했다.
8. 경계 노드(분해 장의 LangGraph)에 「안으로」가 붙어 있었다. 문서의 경계 제스처는 선택과 「위 장으로」뿐이다.
9. 시안. 분해 장의 「결과」 화살표가 아래→위로 가고 라벨이 선에 포개졌다. 바깥 필터를 끄면 「신호」 자리만 홀로 남았다. 실행 장에도 필터가 보여 「처리」를 끄면 실행 노드가 다 사라졌다. 실행 예시 노드 「저장」이 역할 「저장」과 이름이 겹쳤다. 부모에 분해 장이 없는 경계의 「위 장으로」는 아무것도 선택하지 않았다.

## 낮음

10. `structure.png` · `flow.png`(08:00)는 1차 검토 전 화면이다. 「호출」 같은 제어 라벨과 「구조로」 버튼이 있고 문서가 참조하지 않는다.
11. 결론 절 안에 1~3차 경과 문단이 섞여 있었다.
12. Tip 6-1 · 6-2를 인용하면서 출처 목록에 없었다. 「2026-10-16 실측」에 절차 이름이 없었다.
13. 장 · 경계 노드 · 미확인 자리는 화면에 낼 때 용어집 등록이 필요하다. `gap-*`는 기존 「빈틈」(Gaps)과 영어가 같다.
14. 시안 잔여물: 양쪽이 같은 삼항식, `render` 덮어쓰기.

## 반영 (같은 날)

- 1: 분해는 구조 장, 흐름 장은 시나리오만. 상단 버튼도 그렇게 눌린다.
- 2·3: r11~r14 삭제. 미확인 자리는 그릴 때 계산(`slot:<부모 관계 id>`). 관계마다 `evidence`. 근거 없는 선은 점선, 옆 목록에 「미확인」. 자식 선이 있으면 부분에 닿고, 맞는지는 `evidence`가 따로 말한다.
- 4: 「지금 콘솔의 배치」와 「선 그리기」 문단 추가. 옵션 이름은 구현 때 ELK 참조에서 확인한다고 적음.
- 5: `langgraph-run` 장(`kind: run`, `graph`) 추가, 하드코딩 제거.
- 6·7: 경계 · 자리는 계산값이라고 명시. `viewIssues`가 분해 · 시나리오 공통 규칙을 검사. 틀린 선 넷을 넣어 넷 다 잡는 것을 확인.
- 8·9: 경계 노드의 「안으로」 제거. 분해 장 좌표를 위→아래로, 라벨은 곡선 중점 옆. 자리는 맞은편 끝이 보일 때만. 실행 장 필터 숨김, 노드 「마무리」로 바꿈. 「위 장으로」는 가장 가까운 조상을 고름.
- 11·12·13·14: 「검토 이력」 절로 이동, Tip 6-1 · 6-2를 열어 확인 후 출처에 추가, 용어 절 추가, 잔여물 제거.
- 10: 스크린샷은 사용자 지시로 이번에 다루지 않았다. 폴더의 png 다섯 장은 모두 이 판의 시안과 다르다.

시안 실행 확인: 구조 → 커널 「안으로」 → 분해 → 「위 장으로」 → 뒤로 → 위로 → 시나리오 → 실행 → 뒤로 → 흐름 고르기. 범위 문장에 「검사 실패」 없음, 자바스크립트 오류 없음, 폭 400px에서 가로 스크롤 없음. 문서 JSON과 시안의 `elements` · `rels` · `views`는 기계 대조로 같다.
