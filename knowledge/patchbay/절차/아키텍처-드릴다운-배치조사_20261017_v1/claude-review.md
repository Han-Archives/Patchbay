# Claude 독립 검토 원문

2026-10-17. `claude-opus-5-5`. 도구·웹·파일 수정 없이, 조사 문서와 HTML 시안만 보고 쓴 답이다. 중심 질문은 이 결론대로 만들면 흐름·처리·저장을 노드로 보고 눌러 세부로 들어가는 일이 실제로 되는가이다.

**한 줄 판정:** 세 장 분리, 한 번 누름과 안으로의 분리, 장 교체, 한 장씩 그리는 elkjs 위→아래 배치는 이대로 구현해도 됩니다. 반면 그림 데이터(JSON), 균형 규칙, 시안의 경계 노드 표기는 고치지 않으면 화면이 거짓을 보여 줍니다.

## 높음

1. **시나리오와 균형 규칙이 서로 맞지 않습니다.**
   - 근거: 문서는 흐름 장을 「한 장에 시나리오 하나」(arc42 런타임 뷰)로 두면서, 균형은 「부모로 드나드는 선이 자식 경계에 모두 있어야 한다」(DFD)로 정했습니다. 시나리오는 정의상 부모 선의 일부만 씁니다.
   - 시안의 kernel-write에도 부모의 「실행」(커널→LangGraph)이 없고, 부모에 없는 「결과」가 있습니다. 그런데 범위 문장은 균형이 맞는다고 적습니다.
   - 수정: 자식 그림을 두 종류로 나눕니다. `decomposition`은 DFD 균형(부모 선 전부)을 따르고, `scenario`는 부분집합 규칙(모든 선이 부모 관계 중 하나에 대응, arc42 Tip 6-1)을 따릅니다. 팁 번호는 확인하지 못했습니다.

2. **그림마다 노드를 따로 적는 JSON으로는 균형을 기계로 검사할 수 없습니다.**
   - 부모의 `workspace`와 자식의 `store`는 같은 저장소인데 id가 다릅니다. 선을 맞출 수단은 라벨 문자열뿐입니다.
   - 수정: Structurizr처럼 모델(요소·관계, 전역 id)과 뷰(모델의 부분집합)를 나눕니다. 자식 뷰의 경계는 모델에서 부모 요소의 관계로 계산하고, 경계 노드는 `ref`로 원래 요소를 가리킵니다.

3. **경계 대리 노드를 「바깥」으로 그립니다.**
   - 「호출 들어옴」, 「결과 돌려줌」은 시스템 안의 콘솔인데 `external`로 표시됩니다. 시스템 경계가 거짓으로 보입니다.
   - 수정: `boundary` role을 추가하고 상대 요소 이름을 흐린 노드로 그립니다. 누르면 위 장의 그 요소로 갑니다.

4. **저장소 읽기·쓰기 검사를 그림 한 장 단위로 걸면 정상 그림이 실패합니다.**
   - 한 시나리오가 쓰기만 하는 것은 흔합니다(kernel-write). 시안의 구조 장 작업 공간도 쓰기만 있습니다.
   - 수정: 검사는 모델 전체에서 합니다. 뷰에서는 옆 설명에 「읽는 곳: ○○」를 보여 줍니다.

5. **그림이 코드와 맞는지 보장할 장치가 없습니다.**
   - 데이터 원본 결정을 뒤로 미뤘고, 남은 것은 손으로 적는 JSON뿐입니다. 사용자가 보려는 것은 실제 흐름이므로, 그림이 낡는 순간 화면이 거짓이 됩니다.
   - 수정: 요소와 관계마다 근거(IR id, 모듈 경로)와 확인일을 둡니다. 근거를 찾지 못하면 화면에 「미확인」을 표시합니다.

6. **흐름 장은 「순서 있는 데이터」라는데 edge에 순서 칸이 없습니다.**
   - 수정: `step` 칸을 두고, 오류 시나리오용으로 `condition`을 둡니다(C4 동적 그림의 번호).

## 중간

- **목적지 개수:** `childDiagramId`가 단수라서 「목적지가 둘 이상이면 고르는 목록」과 충돌합니다. 배열로 바꿉니다.
- **구조 장의 선 의미:** 「의존 또는 데이터 중 하나」로 열어 두면 저장 흐름이 사라질 수 있습니다. 시안도 호출(제어), 기록(데이터), 실행(제어)을 섞었습니다. 목적에 맞게 데이터로 고정하고, 라벨은 흐르는 것의 이름으로 씁니다.
- **수준과 장:** 「수준 셋」과 「장 셋」이 다릅니다. 실행은 수준이 아니고, 맥락 장은 탭이 없는데 「하지 않음」 항목은 맥락 장을 언급합니다. 맥락을 구조 장의 바깥 노드로 대신한다고 명시합니다.
- **겹치지 않는다는 문장:** 「실행 상태와 설계를 한 노드 스타일에 겹치지 않는다」가 실행 장 정의(설계 위에 상태)와 모순처럼 읽힙니다. 「구조·흐름 장에는 실행 상태를 넣지 않는다」로 고칩니다.
- **LangGraph의 「안으로」:** 일반론(노드 실행→state→다음)이라 실제 그래프가 아닙니다. 목적지는 실행 장이어야 합니다. state를 저장으로 그리는 것은 영속이 켜졌을 때만 참입니다. 실행 장에서 서브그래프를 어떻게 여는지도 정해 둡니다.
- **Shneiderman의 relate:** 일곱 과제 중 relate가 빠졌는데, 이 요청의 중심입니다. 노드를 선택하면 이웃과 선을 강조하는 동작을 넣습니다.
- **배치 엔진:** Dagre와 ELK 두 선택지는 구현을 둘로 만듭니다. 구조 장은 저장소 때문에 트리가 아니므로 elkjs 하나로 갑니다.
- **교체 근거:** 10-16 실측은 가로 배치 실패이지, 위→아래 펼침이 실패한 것은 아닙니다. 다음 경우에는 펼침이 더 낫습니다.
  - 자식이 3~4 노드 이하일 때
  - 「이 기록이 어디서 와서 어디에 남나」처럼 부모의 이웃까지 이어서 따라가야 할 때

  교체를 기본으로 두고 부모 이웃을 경계 노드로 남기면 대부분 해결됩니다.
- **Cockburn 인용:** 왜곡이 해롭다고 「정리한다」는 표현은 단정에 가깝습니다. 연구 결과가 엇갈리는지는 문서만으로 확인하지 못했습니다. 결정에는 영향이 없습니다.

## 시안이 문서와 다른 점

- 실행 장의 빵 부스러기가 「구조 / 실행」이라 실행이 구조 아래 장처럼 보입니다.
- 「안으로」가 노드 안의 글자일 뿐 누를 수 없습니다. 키보드의 Enter는 선택만 합니다.
- 한 번 누름이 SVG를 다시 그리므로, 브라우저에 따라 더블클릭이 동작하지 않을 수 있습니다. 실행해서 확인하지는 않았습니다.
- 위로, 뒤로, 필터, 목적지 목록, 셋째 단이 없습니다.
- 옆 설명이 들어옴과 나감만 세고, 읽는 저장과 쓰는 저장을 구분하지 않습니다.
- 흐름 목록이 부모를 이름 대신 `kernel` id로 보여 줍니다.
- 근거 카드의 「선이 꼬인다」는 문서가 인용한 ELK 한계(옵션·전략 비호환)보다 셉니다.

## 유지해도 되는 결론

- 세 장 분리
- 한 번 누름은 옆 설명, 안으로는 장 교체
- 한 장씩, elkjs 위→아래 배치
- 시나리오는 한 장에 하나
- 복합 노드, 물고기 눈, 코드 단을 쓰지 않음
- 「중요한 것만 연다」는 멈춤 규칙
