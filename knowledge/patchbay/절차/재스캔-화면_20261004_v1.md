## 막힘

신규 등록은 화면(「+ 신규 프로젝트」)에서 스캔까지 했지만, **이미 등록된 프로젝트의 재스캔은
터미널**이었다. 구조 화면이 비어 있으면 `patchbay scan --project <alias>` 를 글자로 보여 줬고,
지식 탭도 같았다. 앞 두 걷기와 같은 모양 — 보여 주기는 하고 시작하기가 없다.

## 정한 것

**쓰기 순서를 Core 하나로 모았다.** 같은 여섯 줄이 CLI `scan` · CLI `project add` · 콘솔
`addProjectView` 세 곳에 복사돼 있었고, 화면 재스캔을 붙이면 네 번째가 될 참이었다. 원칙 8 — 하나가
`FLOW.md` 를 빠뜨려도 시험이 잡지 못한다. 이제 넷 다 `writeScanOutputs` 를 부른다. overlay 는 여전히
건드리지 않는다(사람 것).

**「앞 스캔 없음」과 「항목 0개였음」을 합치지 않았다.** `portsBefore` 는 앞 `inferred.json` 이 없으면
`null` 이다. 화면은 그때 「0 → n」이 아니라 「처음 스캔했다」고 말한다 — 2단계 입구에서 「아직 없다」와
「어긋난다」를 나눈 것과 같은 이유.

**버튼은 구조 화면 안에 둔다.** 스캔이 바꾸는 것이 구조(Atlas)라서, 누른 자리에서 칩과 그래프가 바로
다시 그려진다. 항목 설명(`/api/project/ports`)도 이제 view 가 바뀌면 다시 읽는다 — 새 항목에 설명이 비지
않게.

(`vite build`)와 타입 검사까지, 동작은 API로 걸었다. 다음에 콘솔을 띄우면 구조 → 「다시 스캔」을 한 번
눌러 칩이 바뀌는지 본다.
