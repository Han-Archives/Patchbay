# 코드 대조 결과를 설계 결정과 PRD 초안으로 반영

- 날짜: 2026-10-28
- 범위: Patchbay 코드 대조 1~9장 결과 정리
- 제한: 제품 코드는 수정하지 않고 설계 초안과 기록만 변경

## 결정

1. Patchbay가 띄우는 세션에는 웹 검색과 외부 MCP 호출을 제공하지 않는다. 바깥 세션이 Patchbay MCP 서버를 호출하는 R3.3b는 유지한다.
2. LLM에는 선택한 프로젝트의 L0~L3 프롬프트와 필요한 발췌만, GitHub에는 공개 추적 파일만, 폰 알림에는 상태와 짧은 요약만 보낸다. 자격 증명·L4·다른 프로젝트 원문은 보내지 않는다.
3. 공개 저장소에서는 `.env`, 로그인·인증 파일, API 키·토큰·웹훅, 비공개 기록, 비공개 이름을 제외한다. push는 사람이 요청한 때만 한다.
4. 다시 만들 수 있는 파생 인덱스, 빌드·시험 산출물, 세션 임시 시안만 임시 기록으로 본다. 그 밖의 기록은 삭제 요청 전까지 보존한다.
5. R7.2a의 연관 추천은 실행 전 준비본 수정 요청으로 바꾸고 다시 준비할 수 있다.
6. R4.1a, R8.3·R8.3a~d, R9.4a는 `could`와 다음 판 범위로 분리한다.
7. 요구사항별 합격 예시는 `evals`와 `requirementLinks`로 관리하고 실제 예외만 요구사항 문장에 쓴다. PRD 묶음 노드에는 문서를 억지로 배정하지 않는다.

## 완료 확인

R3.2 화면이 동작하기 전에는 요구사항↔시험 연결, 실행 기록, 아키텍처 구조 원본으로 확인한다. 화면이 동작한 뒤에는 승인 설계와 실행 상태가 같은지도 흐름도에서 확인한다.

## 반영과 검사

- 커널 `applyConsultPatch` 경로로 `ir.proposed.yaml`과 출처 기록만 갱신했다. 채택본 `overlay.yaml`은 바꾸지 않았다.
- 설계 규칙 검사: 43/43 통과.
- 채택본 대비 기능 차이: R7.2a 문장, `cap:external`, `group-r3`, 외부 도구 `web_search`·`external_mcp` 제거.
- 제품 코드 수정·서버 재시작·커밋·push: 하지 않음.

## 수리 검토 항목

- R7.2a 수정 요청 경로가 실제 준비본 재생성과 일치하는지 확인한다.
- 웹 검색·외부 MCP 제거가 R3.3b의 바깥 세션→Patchbay MCP 제공과 혼동되지 않는지 확인한다.
- 공개 전 명백한 키 형식 검사가 현재 자동 장치가 아니라 절차 결정으로만 남은 위험을 확인한다.
- 사람 채택 전까지 초안을 유지한다.
