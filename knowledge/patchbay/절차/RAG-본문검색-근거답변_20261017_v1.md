# RAG 본문 검색과 출처 답변

사용자: “반영해줘”. 검토한 RAG 기획 20261017a의 첫 완성 범위 P0~P2를 제품에 적용했다.

왼쪽 RAG는 질문/자료/검색 점검과 원문 패널로 바뀐다. 자료에서 MD/TXT를 선택하거나 A+B 원문의 검색 사용을 켠다. 질문으로 본문을 찾고, Claude 또는 LM Studio를 직접 선택해 출처가 달린 답변을 생성한다. 인용 번호로 같은 버전의 원문을 확인한다. 기존 설계 연결 검색과 documents HTTP·CLI·MCP는 보존한다.

## 구현

- core `knowledge/rag.ts`: 허용 자료 본문 BM25, NFC·한글 2-gram·영문 식별자, 원문 버전/문자 범위/해시, id+quote 검사. 최대 8개·총 6,000자. 디스크 질의 캐시·색인 없음.
- 공유 `semantic.json`: source usage(retrieval/graph)와 외부 전달 허용, 불변 원문 버전, 프로젝트 잠금·원자 교체. 검색 해제는 승인 관계를 보존. RAG 전용 자료는 A+B 검토 목록에서 제외.
- Flow `ragHost.ts`: 자료/설정/검색/답변/원문/중지 API, 원격 전달 기본 차단, 모델 text 실행과 늦은 응답 폐기. RAG 실행을 불빛·이름 변경 보호·서버 종료에 연결.
- `RoomRunner execution=text`: 빈 임시 cwd, Claude safe-mode·tools/MCP 없음·세션 미보존, 로컬 lms chat. Codex는 도구 없는 실행 계약을 검증하지 못해 초기 생성에서는 비활성.
- `RagPane.tsx`·`rag.css`: 기존 RAG 진입점에 적용. 자료 개정/철회 후 이전 결과 제거, 원문 인용 강조, 모델 자동 선택/목록 조회/추론 없음. 문서 목록도 명시적 버튼에서만 조회.
- 실행 감사는 `knowledge/rag-deliveries.jsonl`에 식별자만 기록. 원문·질문·답변 본문은 보관하지 않음.

실제 Neo4j 시험에서 source usage 객체를 속성으로 직접 전달하던 문제를 발견했다. 관계 저장에는 source id/path만 투영하도록 고쳐 실제 재생·멱등·롤백·격리·재구축 시험을 통과했다. RAG 전용 설정 변경의 순차 no-op 커서도 시험했다.

## 검증

| 확인 | 결과 |
| --- | --- |
| 전체 기본 시험 | 1,249개 통과, 실제 Neo4j 시험 1개는 기본 환경에서 건너뜀 |
| 실제 Neo4j + A+B/RAG core 회귀 | 15개 통과. 임의 시험 alias만 사용 |
| 브라우저 | 35개 확인, 1512/1280/1024/768/390px 내부 가로 넘침 없음 |
| 실제 LM Studio Qwen2.5 14B | 가상 원문의 “90일 보관”을 정확한 인용으로 답변, 약 47초 |
| 실제 Claude CLI sonnet 선택 | 전달 허용한 가상 원문의 “30일 보관”을 정확한 인용으로 답변, 약 3.4초 |
| 자료 10개·질문 30개 | 정확 용어 6/6, 표현 변형 2/6, 명시 관계 4/4, 개정 4/4, 충돌 근거 검색 3/3, 근거 없음 4/4, 비허용 원문 미노출 3/3 |

이 수치는 합성 자료의 스모크 확인이다. 관계/충돌 점수는 검색의 필수 원문 적중이며 답변 품질 점수가 아니다. 모델 실행 시간도 사용자 자료의 성능 약속으로 사용하지 않는다. 원문 문자 일치와 답변의 논리적 지지는 별개다.
