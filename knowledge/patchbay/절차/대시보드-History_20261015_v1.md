# 대시보드 History와 월별 활동 캘린더

작성일: 2026-10-15.

## 사용자 요청과 변경

- 진척 근거·학습 지표 카드를 대시보드에서 제거했다. 기존 시험·테스트 데이터와 API는 유지한다.
- ‘최근 기록’을 **History**로 바꾸고 날짜·태그·내용 3개 열로 표시한다. 기존 진행 기록의 단계/스킬을 태그로 표시하고, 요청·실제 변경 내용은 펼쳐 볼 수 있다.
- ‘기록 추가’에서 날짜·태그·내용을 직접 저장한다. 태그는 쉼표로 구분해 최대 6개, 내용은 5,000자까지다. 수동 기록을 진행 상태의 current로 만들지 않도록 별도 저장한다.
- 오른쪽에 GitHub 활동 기록처럼 기록 수에 따라 색 농도가 달라지는 월별 캘린더를 배치했다. 날짜를 누르면 그날의 History로 필터하며, 다시 누르거나 ‘월 전체’로 해제한다.
- 이전/다음 달, 월 선택, 오늘, 기록 없는 날짜를 지원한다. 좁은 화면에서는 캘린더를 목록 위로 배치한다.

GitHub 연동 기능은 추가하지 않았다. 활동 기록 형식의 캘린더이며 실제 데이터는 Patchbay의 진행·수동 기록이다. 자동 기록은 브라우저 현지 날짜, 수동 기록은 사용자가 지정한 날짜로 묶는다.

## 구현

- 화면: `DashboardPane.tsx`, `DashboardHistory.tsx`, `historyContract.ts`, `console.css`.
- API: `GET/POST /api/dashboard/history`. 기존 세션 인증, 조회/쓰기 권한과 출처 검사를 적용한다.
- 커널: `types/dashboardHistory.ts`, `studio/dashboardHistoryStore.ts`. 날짜·태그·내용 검증과 직렬화·원자 저장.
- 원문: `projects/<alias>/dashboard-history.json`. 기존 `progress.yaml`과 합쳐 조회한다. 저장구조·접근 등급·아키텍처·개요를 함께 갱신했다.

## 검증

Core 빌드, Flow 형검사·클라이언트 및 서버 빌드 통과. History 5개, 대시보드 6개, 진행 저장 18개, 서버 37개: 서로 다른 시험 총 66개 통과.

Chrome 임시 작업 공간에서 기존 카드 제거, 날짜·태그·내용 표시, 오른쪽 캘린더 배치와 격자 넘침, 일자 필터, 기록 추가·태그·새로고침 후 보존, 이전 달 조회, 윤년 2월 29일, 빈 날짜, 모바일 가로 넘침과 런타임 오류를 확인했다.
