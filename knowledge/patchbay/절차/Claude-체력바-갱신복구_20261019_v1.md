# Claude 체력바 사용률 갱신 복구 · 2026-10-19

요청: 사용률 수신 지연과 부분 갱신으로 변하지 않던 Claude 체력바를 수정한다.

## 변경

- `core/src/studio/llmQuotaStore.ts`: session/weekly 각각의 관측 시각을 저장한다. 파일 잠금 뒤 부분 병합하며, 누락된 창을 지우거나 그 관측 시각을 새로 찍지 않는다. 지연된 오래된 입력도 최신 창을 덮지 못한다. 기존 파일의 최상위 at를 읽어 호환한다.
- `flow/src/claudeQuotaHost.ts`: 로그인된 Claude CLI에 initialize/get_usage 제어 요청만 보내 최신 사용률을 받는다. 사용자 메시지·모델 턴·도구·MCP를 보내지 않는다. CLI의 실험적 사용률 조회 경로이며 설치된 Claude Code 2.1.296에서 실제로 확인했다. 분당 최대 한 번, 동시 조회 합침, 12초 제한, 응답 크기 제한과 프로세스 정리를 둔다.
- `serve.ts`가 실제 조회를 주입하고 `GET /api/llm-quota`에서 집계 전에 실행한다. 단위 시험과 임시 앱은 주입하지 않으면 실제 CLI를 실행하지 않는다. Core는 프로세스나 모델을 실행하지 않는다. CLI 자격 증명을 직접 읽거나 복사하지 않는다.
- `LlmHealthRail.tsx`: 최신 두 창의 최솟값을 표시한다. 한 창만 확인되면 확인된 비율과 기준 기간을 표시한다. 5분 이상 지난 값이나 리셋 시각을 지난 값은 현재 %로 쓰지 않고 마지막 관측과 갱신 대기를 표시한다. 상세에는 창별 확인 시각을 보인다.
- CLI 상태줄도 리셋 시각만 보고 임의의 100%를 만들지 않고 새 관측을 기다린다.

Claude 공식 문서는 각 사용률 창이 따로 생략될 수 있고 리셋 시각을 지나면 창을 생략한다고 설명한다. 이를 정상 입력으로 처리한다. [Claude Code 상태줄 문서](https://code.claude.com/docs/en/statusline#available-data).

## 검증

- 모노레포 빌드와 Flow 타입 검사·프로덕션 빌드 성공.
- 관련 시험 59개 통과: 사용률 저장 9, CLI 제어 조회 5, HTTP 서버 42, 상태줄 3. 아키텍처 관련 10개도 통과.
- Chrome 격리 검증 14개 통과: 실제 15초 조회에서 65%→55% 반영, 주간만 있을 때 92%·7일 기준 표시, 오래된 값은 갱신 대기·마지막 확인 비율로 구분, 누락 시 비율 생성 없음, 새 관측 후 95% 복구, 모바일 팝오버 화면 안 배치. 모델 호출과 브라우저 오류 0.
- 현재 4318 반영 뒤 실제 관측 4개 확인: 두 창 최신 수신, 잔여 체력 존재, API와 레일 일치, 상세 관측 시각 표시. 실제 계정 값과 캡처는 비공개 기록층에 보관한다.
- 실제 네이티브 조회에서 제어 응답만 2개 수신했다. 추론 메시지를 전송하지 않았다.

재시작 시 진행 중인 LLM 작업을 감지해 먼저 보류했고, 작업이 없는 상태를 확인한 뒤 기존 접속 설정을 보존해 재시작했다. 아키텍처·저장 구조 문서와 현재 아키텍처 배치도도 반영했다. 현재 사용 중인 브라우저는 새로고침하면 새 표시가 적용된다.

## 제한

get_usage는 Claude SDK의 실험적 경로라 CLI 변경·로그인·네트워크 상태에 따라 실패할 수 있다. 실패하면 기존 관측은 보존하고 관측 시각에 따라 갱신 대기로 전환한다. 새 사용률을 받은 것으로 시각만 갱신하거나 추론 호출로 대신하지 않는다.
