# History 배치·스크롤·기능 영역 태그

작성일: 2026-10-15.

사용자 요청: History 옆이면서 할일 아래에 캘린더 배치, History는 5개 이상 내부 스크롤, 태그는 UI·LLM·대화창 같은 큰 기능 영역으로 표시.

## 변경

- 대시보드 2열 격자를 위쪽 ‘흐름도 / 할일’, 아래쪽 ‘History / 캘린더’로 구성했다. 두 카드가 나란히 시작하며, 모바일에서는 한 열로 표시한다.
- History 표의 제목 행과 첫 5개 기록 행의 실제 높이를 측정한다. 6번째부터는 표 내부 스크롤로 확인하고 날짜 변경 때 스크롤을 위로 돌린다. 화면 너비나 펼친 내용이 바뀌면 높이를 다시 계산한다.
- 수동 기록 태그는 **UI·LLM·대화창·할일·대시보드·데이터·서버·문서·프로젝트** 중 기능 영역을 선택한다. ‘진행·수정·검증’ 같은 단계/상태 태그의 신규 입력은 API에서도 거절한다.
- 기존 수동 기록의 유효한 영역 태그는 유지한다. 그 외 옛 태그와 자동 진행 기록은 내용·단계·요청·변경 설명을 기준으로 표시용 영역을 분류한다. 원문은 바꾸지 않는다. 식별할 근거가 없는 항목은 ‘프로젝트’로 표시한다.
- 캘린더의 날짜 필터와 기존 ‘Log에서 보기’ 연결을 유지했다.

## 검증

Flow 형검사·클라이언트 및 서버 빌드 통과. History 6개·대시보드 6개·서버 37개, 총 49개 시험 통과.

Chrome 임시 작업 공간에서 캘린더가 할일 아래/History 오른쪽인지, History와 캘린더의 위쪽 정렬, 정확한 첫 5개 행 높이 및 내부 스크롤, 단계 태그 제거, 날짜 필터, UI/LLM 태그 선택·저장·새로고침 보존, 모바일 가로 넘침과 런타임 오류를 확인했다.
