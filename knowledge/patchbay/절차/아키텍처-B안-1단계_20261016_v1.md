# 아키텍처 화면 B안 1단계 · 2026-10-16

요청: 레일 「아키텍처」가 실제 구조와 무관한 고정 설명이었다. 흐름도로 보이고 노드를 누르면 상세가 열리며, LangGraph를 화면에서 부르고 MCP를 붙일 수 있게. 변경은 검토 → 의견 → 변경을 거쳐 Review의 「달라진 점」으로. 시안 4개(계층 · LangGraph 실행 · 연결 지도 · 변경 보기) 중 **B(LangGraph 실행 캔버스)** 를 골랐다.

정한 것(사용자): 설계가 없는 프로젝트는 빈 화면 + 「설계 시작」 · MCP 붙이기는 서버에 실제로 접속해 도구 목록을 받는다 · 「의견」은 상담 호스트(Claude Code · Codex)가 낸다. 세 단계로 나눠 단계마다 보여 준다.

## 반영 (1단계 — 화면과 실행)

- `ArchitecturePane.tsx`: 승인된 설계(`/api/ir?source=current`)를 `toIrCanvas`로 그리고 위에서 아래로 흐르게 놓는다(가로로 두면 6단 그래프가 반 크기로 줄어 못 읽었다). 설계의 `graph` 칸과 같은 LangGraph 그래프, 그 그래프의 가장 최근 스레드(`metadata.graph_id`) 상태를 겹친다 — 「● 지금」 · 「✓ 실행됨」.
- 노드를 누르면 오른쪽에 들어옴 · 나감 · 읽는/쓰는 state · 모델(공급자) · 도구(코드/MCP · 서버 · 권한) · 문서 · 요구사항, 「▶ 이 노드만 실행」. 위에는 「▶ 그래프 실행」 · 입력 편집 · 다시 연결, 아래에는 체크포인트 레일(`FlowPane`의 것을 그대로 씀).
- 「이 노드만 실행」: `POST /api/flow/runs` 에 `node` — 그 노드를 다음으로 기다리던 가장 최근 체크포인트에서 갈라 `interrupt_after: [node]`. 닿은 적 없으면 409. LangGraph에 노드 하나만 부르는 API는 없다(앞 노드가 만든 state가 입력).
- 스레드 목록은 그래프를 가리지 않아서(실측: 최신 스레드가 다른 그래프 것) `FlowThreadView.graphId` 를 더했다.
- 설계가 없거나 초안만 있으면 빈 화면: 「설계 시작」/「설계 이어 쓰기」 · 「구조 그래프는 폴더 · 문서에서」.
- 레일 아이콘을 연결된 상자 셋으로. 옛 `SystemArchitecturePanel.tsx` 는 `.trash/2026-10-16`, 그것만 쓰던 CSS는 뺐다.
