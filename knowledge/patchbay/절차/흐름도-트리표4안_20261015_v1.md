# 흐름도 트리표 4안 · 2026-10-15

사용자 요청: [흐름도-세부작업표4안](흐름도-세부작업표4안_20261015_v1.md) 중 트리 표로 진행하되 흐름도는 그대로 둔다. 표는 항목명 · 설명 · 태그 · 실행 버튼 구조로 명시한다. 항목명은 업무명이며 7글자를 넘으면 뒤를 「...」로 줄인다. 설명은 무엇을 하는지 짧게. 태그는 가장 위 분류(UI, Agent 등). 이 요구에 맞춘 표 수정 산출물 4가지.

상태: 승인 대기. 독립 HTML 시안이며 제품 코드는 바꾸지 않았다. 예시 데이터만 쓴다.

## 공통

- 열: 항목명 · 설명 · 태그 · 실행. 작업 행과 세부 행이 같은 열을 쓴다. 작업 행 태그 칸은 아래 세부 항목 태그를 모아 보인다.
- 항목명: 띄어쓰기 · 가운뎃점 포함 8글자부터 앞 7글자 + 「...」(끝 공백은 지움). 마우스를 올리면 전체 이름.
- 태그: UI · Agent · 데이터 · 서버 · 문서 (시안용 다섯 개 — 확정 목록 아님).
- 실행: ▶ 로 할일 맨 아래에 올림, 이미 올린 항목은 다시 못 올림. − 빼기. 맨 아래 + 는 네 칸을 그대로 입력하는 줄.
- 앞 시안의 체크(끝냄)는 요청한 구조에 없어 뺐다. 흐름도 칸 막대는 그래서 「할일에 올린 비율」로 바꿨다.

## 버전

| 안 | 이름 | 차이 |
| --- | --- | --- |
| 1 | 기본 네 칸 | 무채색 태그 칩, ▶ · −. 항목명 앞 점으로 LLM 계획 / 직접 추가 |
| 2 | 태그 색 구분 | 태그별 색, 세부 행 왼쪽 색 띠, 작업 행 태그에 개수 |
| 3 | 한 줄 · 태그 필터 | 촘촘한 한 줄 행, 표 위 태그 필터로 그 태그만 펼쳐 보기 |
| 4 | 실행 강조 | 「▶ 할일로」 글자 버튼, 올린 뒤 「할일 #n」, 작업 행 「▶ 남은 것 모두」, 설명 아래 출처 |

## 구현 때 정할 것

- 최상단 태그 목록 확정, 그리고 LLM이 Plan할 때 태그를 고르게 할지
- 세부 항목 저장 필드: 이름 · 설명 · 태그 · 출처 · 할일 연결
