# 할일 디자인 검토 — 2026-10-14

상태: 승인 대기. 이번 산출물은 독립 HTML 시안이며 제품 구현은 승인 후 진행한다.

시안: [화면 열기](할일-디자인_20261014_v1/index.html)

## 화면과 동작

- 제목 바로 오른쪽에 오늘 날짜, 각 항목에는 등록일을 표시한다. 제목 줄 오른쪽 끝 +로 제목·요구사항을 입력해 목록 하단에 추가한다.
- ‘다음 할 일’ 문구를 제거한다. 각 행 앞의 원형을 세로선으로 연결하여 위에서 아래의 실행 순서를 보여준다.
- 실제 수행 중인 연결 작업에만 보라색 점멸을 표시한다. 입력 대기·실패·중단·완료에서는 점멸을 멈춘다. 동작 줄이기 설정에서는 고정 불빛과 텍스트를 사용한다.
- 드래그 손잡이로 대기 항목을 재정렬한다. 키보드 ↑↓와 모바일 이동 메뉴도 제품 구현에 포함한다. 진행 중인 항목은 고정한다. 순서 변경은 서버에 저장한다.
- 행 오른쪽 … → 대화창 만들기. 제목과 요구사항이 담긴 전용 대화를 만들고 해당 대화로 이동한다. 이미 연결된 대화가 있으면 대화창 열기로 표시하여 중복 생성하지 않는다.
- 대화 생성 후 시작 버튼으로 실제 실행한다. 순서대로 진행하며 완료 후 다음 항목을 시작할 수 있게 한다. 자동 연속 호출은 이번 제안에 포함하지 않는다.
- 완료된 항목은 취소선을 적용하고 하단 ‘완료된 할일’로 이동한다. 완료 날짜·시간을 표시하며 한 행 높이로 제한해 2건부터 스크롤한다.
- 완료 시각부터 72시간 동안만 메인에 표시한다. 시간은 저장 시 ISO 형식, 표시는 사용자 현지 시간대로 한다.

## 기록과 검색을 위한 설계

현재 todos.json에는 id/title/detail/done/at만 있고, 대시보드의 일부 완료 표시는 localStorage에 저장된다. 구현 시 순서·상태·완료 시각·room ID를 서버의 영속 데이터로 통합해야 한다. 자동 생성된 단계·막힘 항목은 출처를 보존하고 동일한 목록에서 중복 없이 다룬다.

제안 보관 위치: `~/.patchbay/projects/<alias>/todo-history/`.

```text
todo-history/
  index.json             # 검색 프로그램용 목록
  index.md               # 사람이 읽는 테이블
  <todo-id>/
    task.json            # ID, 원문 요구사항, 등록/시작/완료 시각, 상태, 순서, room IDs
    summary.md           # 요구사항, 수행 결과, 산출물 경로, 검색용 본문
    conversations/
      <room-id>.json     # 연결된 대화 원본 보관
      <room-id>.md       # 검색용 대화 본문
```

완료 즉시 기록을 저장한다. 3일이 지나면 메인 목록에서만 숨긴다. index의 열은 할일 ID·제목·등록일·완료 시각·대화 ID·요약·태그·폴더 경로다. 할일 ID와 대화 ID로 검색 결과에서 원문을 찾는다. 대화가 완료 이후 갱신되면 보관본과 index도 갱신하며 실패하면 저장 실패와 재시도를 표시한다. 실제 RAG 색인 연결 여부는 구현 단계에서 기존 문서 호출 경로를 확인해 검증한다.

날짜는 등록일 기준, 최근 3일은 완료 후 72시간 기준으로 제안한다. 진행 중 항목은 고정하며 대화 생성과 작업 시작은 두 동작으로 나눈다. 시안의 샘플 버튼은 메모리 내에서만 동작하며 실제 LLM 호출·파일 보관을 하지 않는다.
