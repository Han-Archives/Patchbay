# 실제 프로젝트 대화창 크기 조절 수정

- 작성일: 2026-11-03 (Asia/Seoul)
- 사용자 요청: 대화창을 늘리는 기능이 제대로 동작하지 않아 문제를 해결한다.

## 확인한 원인

실제 `App.tsx`에는 대화창 크기 조절이 연결되어 있지 않았다. 2026-11-02의 독립 시안에만 경계 드래그·확대/복원이 있었다. 시안에서는 1280px 창의 작업 최소 800px 제한으로 대화 열이 360→372px만 늘어났다. 이는 최소 폭 보호에 따른 제한이며 확대 버튼은 740px로 정상 동작했다.

## 수정

실제 프로젝트 화면에 `useChatLayout.ts`·`chatLayout.css`를 연결하고 `RoomPanel` 머리에 확대/복원 버튼을 추가했다.

- 경계 드래그·방향키, Shift+방향키, Home/End, 더블클릭 초기화를 제공한다. 기본 열 너비 310/340px를 유지하며 변경한 너비는 브라우저에 저장한다.
- 작업 최소 800px를 기준으로 드래그 확대를 제한한다. 이미 좁은 화면에서는 기존 기본 대화 폭을 유지하며 더 넓은 보기는 별도 확대 버튼으로 연다. 모바일에는 경계선을 숨긴다.
- 확대는 작업 화면 위로 겹쳐 열어 작업 칸 너비를 바꾸지 않는다. 같은 대화 패널과 입력 요소를 유지하며 Esc·복원 버튼·배경 클릭으로 이전 분할로 돌아간다. 확대 중 작업 본문은 inert이고 대화 안에서 Tab 포커스를 순환한다.
- 최소화·다시 펼치기도 입력을 보존한다. 기존 요구사항 화면에만 적용되던 최소화 열 축소를 프로젝트 화면 전체에 연결했다.
- API·모델 호출·대화방 실행 계약은 바꾸지 않았다. 실행 중 서버는 빌드한 정적 화면 파일을 바로 제공하므로 서버 재시작은 필요하지 않다.

## 검증

Flow 타입 검사·프로덕션 빌드와 임시 작업 공간의 Chrome 확인 11묶음을 통과했다. 1536px에서 드래그·키보드·너비 저장을 확인하고, 1366/1280/1024/850/720/390px에서 배치·확대·복원·입력 보존·페이지 가로 넘침 없음을 확인했다. 크기 조절 구간에서 추가 쓰기 요청과 JavaScript 오류는 없었다. 실제 모델 스트리밍·첨부·진행 중 실행의 상태 보존은 이번 검증 범위에 포함하지 않았다. 전체 시험은 실행하지 않았다.
