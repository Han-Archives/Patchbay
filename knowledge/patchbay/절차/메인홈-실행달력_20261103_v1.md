# 메인화면 코드 실행 달력 연결

작성일: 2026-11-03

사용자 요청: 오른쪽 아래 코드 실행 부분도 제대로 구현한다.

## 원인과 변경

기존 집계는 `test-runs/`만 읽어 Claude·Codex의 평소 명령 실행을 빠뜨렸다. 날짜를 눌러도 횟수 외에는 볼 수 없었다. 이번에는 완료된 셸 명령까지 포함하는 것으로 구현했다.

- `homeExecution.ts`: Claude의 Bash 완료 결과와 Codex 완료 명령 이벤트·기존 실행 결과를 읽는다. 대화·파일 편집·커밋·승인 거절·완료 전 호출·백그라운드 시작 통보는 세지 않는다. 원본 ID로 중복을 제거한다.
- 등록 경로 중 가장 구체적인 경로에 명령을 배정한다. 숨긴 프로젝트는 기본 집계에서 제외하고, 날짜·월은 서버 현지 시간으로 묶는다. 원문 명령·출력·대화는 API에 보내거나 새 파일로 복사하지 않는다. 파일 수정 시각/크기별 메모리 캐시만 사용한다.
- `serve.ts`에서만 호스트 경로를 연결하고 시험에서는 임시 원본을 주입한다. 기존 테스트 실행과 합산하되 Claude·Codex·테스트 건수를 나눠 표시한다. 명령 1건·수집된 테스트 실행 1건을 각각 1회로 세므로, 명령으로 시작해 수집된 테스트는 두 종류의 기록으로 표시될 수 있다.
- 선택 날짜의 프로젝트·종류별 횟수와 실패 건수를 보인다. 명령 내역은 프로젝트 화면, 테스트 내역은 해당 프로젝트 테스트 화면으로 이동한다. 월 이동 중에는 이전 달의 숫자를 보여 주지 않고 로딩을 표시한다.
- 잘못된 줄·읽기 실패를 안내한다. 미수집 외부 실행이나 완료 결과를 확인할 수 없는 백그라운드 실행은 추정해 채우지 않는다. 조회 갱신은 기존 15초 주기와 화면 복귀를 사용한다.

## 검증과 적용

- 집계·API 시험 15개 통과. 중복, 실패, 숨김/중첩 프로젝트, 다른 경로, 미래/다른 달, 자정, Claude 거절/미완료, 캐시 갱신, 원문 미전송, 인증을 확인했다.
- Flow 타입 검사·제품 빌드 통과.
- Chrome 7묶음 통과: 실제 형식 명령과 테스트 합계, 날짜별 실패, 프로젝트/테스트 화면 이동, 월 이동, 로딩, 실행 추가 후 갱신, 1536/1000/390px 배치. 브라우저 오류 0건.
- 기존 작업이 끝나길 기다린 뒤 서버의 자체 재시작으로 4318에 적용했다. 실제 호스트 기록 집계, 월 이동, 모바일 표시와 오류 없음까지 확인했다.
